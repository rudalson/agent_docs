# Claude가 목표를 향해 계속 작업하도록 유지하기

> `/goal`을 사용하여 완료 조건을 설정하면 조건이 충족될 때까지 Claude가 여러 턴에 걸쳐 계속 작업합니다.

<Note>
  `/goal`을 사용하려면 Claude Code v2.1.139 이상이 필요합니다.
</Note>

`/goal` 명령은 완료 조건을 설정하며, Claude는 각 단계마다 사용자가 프롬프트를 입력하지 않아도 해당 목표를 향해 계속 작업합니다. 각 턴이 끝난 후, 작고 빠른 모델이 조건이 충족되었는지 확인합니다. 조건이 충족되지 않으면 Claude는 사용자에게 제어권을 돌려주는 대신 다른 턴을 시작합니다. 조건이 충족되면 목표는 자동으로 해제됩니다.

검증 가능한 최종 상태가 있는 상당한 규모의 작업에 목표를 사용하세요:

* 모든 호출 위치가 컴파일되고 테스트가 통과될 때까지 모듈을 새 API로 마이그레이션
* 모든 수용 기준이 충족될 때까지 디자인 문서 구현
* 각 모듈이 크기 예산 미만이 될 때까지 대용량 파일을 집중된 모듈로 분할
* 대기열이 비워질 때까지 태그가 지정된 이슈 백로그 작업 진행

## 세션을 계속 실행하는 방법 비교

세 가지 접근 방식을 통해 프롬프트 사이에 현재 세션을 계속 실행할 수 있습니다. 다음 턴을 시작해야 하는 기준에 따라 선택하세요:

| 접근 방식                                                            | 다음 턴 시작 시점          | 중단 시점                                      |
| :------------------------------------------------------------------ | :------------------------- | :---------------------------------------------- |
| `/goal`                                                             | 이전 턴이 끝날 때         | 모델이 조건 충족을 확인할 때           |
| [`/loop`](/docs/en/scheduled-tasks#run-a-prompt-repeatedly-with-%2Floop) | 시간 간격이 경과할 때      | 사용자가 중지하거나 Claude가 작업 완료를 결정할 때 |
| [Stop 훅](/docs/en/hooks-guide#prompt-based-hooks)                     | 이전 턴이 끝날 때         | 자체 스크립트 또는 프롬프트가 결정할 때               |

`/goal`과 Stop 훅은 모두 매 턴이 끝난 후 실행됩니다. `/goal`은 세션 범위를 갖는 단축키입니다. 조건을 입력하면 현재 세션 동안만 활성화됩니다. Stop 훅은 설정 파일에 상주하며 범위 내 모든 세션에 적용되고, 결정론적 검사를 위한 스크립트나 모델 평가 검사를 위한 프롬프트를 실행할 수 있습니다.

[Auto 모드](/docs/en/auto-mode-config) 단독으로는 단일 턴 내에서 도구 호출을 승인하지만 새 턴을 시작하지는 않습니다. Claude는 작업이 완료되었다고 판단되면 중단합니다. `/goal`은 매 턴 후 조건을 검사하는 별도의 평가기를 추가하므로 완료 여부는 작업을 수행하는 모델이 아닌 새로운 모델에 의해 결정됩니다. 두 기능은 상호 보완적입니다. auto 모드는 도구별 프롬프트를 제거하고, `/goal`은 턴별 프롬프트를 제거합니다.

<Tip>
  위의 접근 방식은 현재 세션을 계속 실행합니다. 야간 테스트나 아침 트리아지와 같이 열려 있는 세션과 독립적으로 실행되는 작업을 예약할 수도 있습니다. 클라우드 루틴 및 데스크톱 예약 작업에 대해서는 [예약 옵션 비교](/docs/en/scheduled-tasks#compare-scheduling-options)를 참조하세요.
</Tip>

## `/goal` 사용법

세션당 하나의 목표만 활성화할 수 있습니다. 인수 형태에 따라 동일한 명령으로 목표를 설정, 확인 및 해제합니다.

### 목표 설정

`/goal` 뒤에 만족하려는 조건을 입력하여 실행합니다. 이미 활성화된 목표가 있으면 새 목표가 이를 대체합니다.

```text theme={null}
/goal test/auth의 모든 테스트가 통과하고 린트 단계가 깨끗함
```

목표를 설정하면 조건 자체를 지시사항으로 삼아 즉시 턴이 시작됩니다. 별도의 프롬프트를 보낼 필요가 없습니다. 목표가 활성화되어 있는 동안 `◎ /goal active` 표시기가 목표 실행 시간을 나타냅니다.

목표 설정이 권한을 변경하지는 않습니다. 기본 권한 모드에서 Claude는 위 예시의 테스트 명령과 같이 설정에서 아직 허용되지 않은 도구 호출 전에 여전히 사용자에게 확인을 요청합니다. 목표 턴이 사용자 개입 없이 실행되도록 하려면 `/goal`을 [auto 모드](/docs/en/auto-mode-config)와 함께 사용하세요.

각 턴이 끝난 후 평가기는 조건이 충족되었는지 여부를 설명하는 짧은 이유를 반환합니다. 가장 최근의 이유가 상태 보기와 트랜스크립트에 나타나므로 Claude가 다음에 무엇을 위해 작업하고 있는지 확인할 수 있습니다.

<Note>
  목표는 조건이 충족되거나 `/goal clear`를 실행할 때까지 계속 실행됩니다. 지금까지 사용된 턴 수와 토큰 수를 보려면 인수 없이 `/goal`을 실행하세요.
</Note>

### 효과적인 조건 작성

[평가기](#how-evaluation-works)는 Claude가 대화에서 제시한 내용과 사용자의 조건을 비교하여 판단합니다. 평가기는 스스로 명령을 실행하거나 파일을 독립적으로 읽지 않으므로, Claude 자체 출력이 입증할 수 있는 형태로 조건을 작성하세요. " `test/auth` 의 모든 테스트 통과"라는 조건이 잘 작동하는 이유는 Claude가 테스트를 실행하고 그 결과가 트랜스크립트에 기록되어 평가기가 읽을 수 있기 때문입니다.

여러 턴에 걸쳐 유효하게 동작하는 조건은 보통 다음과 같습니다:

* **하나의 측정 가능한 최종 상태**: 테스트 결과, 빌드 종료 코드, 파일 수, 빈 대기열
* **명시된 검사 방법**: "`npm test` 가 0을 반환함" 또는 "`git status` 가 깨끗함"과 같이 Claude가 증명해야 하는 방법
* **중요한 제약 조건**: "다른 테스트 파일은 수정되지 않음"과 같이 진행 과정에서 변경되어서는 안 되는 사항

조건은 최대 4,000자까지 작성할 수 있습니다.

목표가 얼마나 오래 실행될지 제한하려면 `or stop after 20 turns`(또는 20턴 후 중지)와 같은 턴 수 또는 시간 절을 조건에 포함하세요. Claude는 각 턴마다 해당 절에 대한 진행 상황을 보고하고 평가기는 대화 내용으로부터 이를 판단합니다.

### 상태 확인

현재 상태를 보려면 인수 없이 `/goal`을 실행하세요.

```text theme={null}
/goal
```

목표가 활성화되어 있으면 상태에 다음 항목이 표시됩니다:

* 설정된 조건
* 실행된 시간
* 평가된 턴 수
* 현재 토큰 사용량
* 평가기의 가장 최근 사유

첫 번째 평가가 실행된 후 턴 수와 가장 최근 사유가 표시됩니다.

활성 목표는 없지만 이전에 세션에서 목표가 달성된 경우, 상태에 달성된 조건과 함께 소요 시간, 턴 수, 토큰 사용량이 표시됩니다.

### 목표 해제

조건이 충족되기 전에 활성 목표를 제거하려면 `/goal clear`를 실행하세요.

```text theme={null}
/goal clear
```

Claude는 확인을 위해 `Goal cleared:` 뒤에 해당 조건을 출력하거나, 활성화된 목표가 없는 경우 `No goal set`을 출력합니다.

`stop`, `off`, `reset`, `none`, `cancel`은 `clear`의 별칭으로 허용됩니다. 새 대화를 시작하기 위해 `/clear`를 실행해도 활성화된 목표가 제거됩니다.

### 활성 목표가 있는 상태에서 재개

세션이 종료될 때 여전히 활성화되어 있던 목표는 `--resume` 또는 `--continue`로 해당 세션을 재개할 때 복원됩니다. 조건은 유지되지만, 재개 시 턴 수, 타이머, 토큰 사용 기준점은 모두 초기화됩니다. 이미 달성되었거나 해제된 목표는 복원되지 않습니다.

### 비대화형(Non-interactive)으로 실행

`/goal`은 [비대화형 모드](/docs/en/headless), [데스크톱 앱](/docs/en/desktop), [Remote Control](/docs/en/remote-control)을 통한 실행에서 동작합니다. `-p`로 목표를 설정하면 단일 실행에서 완료될 때까지 루프가 실행됩니다:

```bash theme={null}
claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"
```

기본 텍스트 출력에서는 조건이 충족될 때까지 아무것도 출력되지 않으므로, 여러 턴을 실행하는 목표는 멈춘 것처럼 보일 수 있습니다. 루프가 실행됨에 따라 각 메시지를 내보내려면 `--output-format stream-json --verbose`를 추가하세요.

조건이 충족되기 전에 비대화형 목표를 중단하려면 Ctrl+C로 프로세스를 중단하세요.

## 평가 작동 방식

`/goal`은 세션 범위를 갖는 [프롬프트 기반 Stop 훅](/docs/en/hooks#prompt-based-hooks)을 둘러싼 래퍼입니다. Claude가 턴을 마칠 때마다 지금까지의 조건과 대화 내용이 설정된 [작고 빠른 모델](/docs/en/model-config)(기본값: Haiku)로 전송됩니다. 모델은 예/아니오 결정과 짧은 사유를 반환합니다. "아니오"는 Claude에게 작업을 계속하도록 지시하고 다음 턴의 지침으로 사유를 포함합니다. "예"는 목표를 해제하고 트랜스크립트에 달성 기록을 남깁니다.

평가기는 세션에 대해 설정된 제공자(provider)에서 실행됩니다. 도구를 호출하지 않으므로 Claude가 대화에서 이미 노출한 내용만 판단할 수 있습니다.

<Note>
  평가 토큰은 제공자에 설정된 작고 빠른 모델 기준으로 청구되며, 일반적으로 메인 턴 사용량에 비해 무시할 수 있는 수준입니다.
</Note>

## 요구 사항

`/goal`은 신뢰 대화 상자를 수락한 작업 공간에서만 실행됩니다. 평가기가 훅 시스템의 일부이기 때문입니다. 또한 설정 수준에서 [`disableAllHooks`](/docs/en/hooks#disable-or-remove-hooks)가 설정되어 있거나 관리형 설정에서 [`allowManagedHooksOnly`](/docs/en/settings#hook-configuration)가 설정되어 있는 경우 `/goal`을 사용할 수 없습니다. 각 경우 명령은 아무 반응 없이 지나치는 대신 원인을 알려줍니다.

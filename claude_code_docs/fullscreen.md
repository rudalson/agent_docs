# 전체 화면 렌더링 (Fullscreen rendering)

> 마우스 지원과 긴 대화에서의 안정적인 메모리 사용량을 갖춘 매끄럽고 깜빡임 없는 렌더링 모드를 활성화하세요.

<Note>
  전체 화면 렌더링은 수동으로 선택하는 [리서치 프리뷰(research preview)](#research-preview) 기능입니다. 현재 대화에서 전환하려면 `/tui fullscreen`을 실행하세요. 피드백에 따라 동작이 변경될 수 있습니다.
</Note>

전체 화면 렌더링은 Claude Code CLI를 위한 대안 렌더링 경로로, 화면 깜빡임을 피하고 긴 대화에서도 메모리 사용량을 일정하게 유지하며 마우스 지원을 추가합니다. `vim`이나 `htop`처럼 터미널의 대안 화면 버퍼(alternate screen buffer)에 인터페이스를 그리며 현재 보이는 메시지만 렌더링합니다. 이렇게 하면 각 업데이트 시 터미널로 전송되는 데이터 양이 줄어듭니다.

차이점은 VS Code 통합 터미널, tmux, iTerm2와 같이 렌더링 처리량이 병목인 터미널 에뮬레이터에서 가장 뚜렷하게 나타납니다. Claude가 작업하는 동안 터미널 스크롤 위치가 맨 위로 튀거나 도구 출력이 스트리밍될 때 화면이 번쩍이는 경우 이 모드가 이를 해결해 줍니다.

<Note>
  전체 화면이라는 용어는 `vim`이 하는 방식처럼 Claude Code가 터미널의 그리기 표면을 제어하는 방식을 설명합니다. 터미널 창을 최대화하는 것과는 무관하며 모든 창 크기에서 작동합니다.
</Note>

## 전체 화면 렌더링 활성화하기

Claude Code 대화 내부에서 `/tui fullscreen`을 실행하세요. CLI는 [`tui` 설정](/docs/en/settings#available-settings)을 저장하고 대화 내용을 유지한 채 전체 화면으로 다시 시작되므로 세션 중간에 컨텍스트 손실 없이 전환할 수 있습니다. 클래식 렌더러로 되돌리려면 `/tui default`를 실행하고, 현재 활성화된 렌더러를 확인하려면 인수 없이 `/tui`를 실행하세요.

[스크린 리더 모드](/docs/en/accessibility)에서 Claude Code는 여전히 전체 화면으로 렌더링되는 연결된 [백그라운드 세션](/docs/en/agent-view)을 제외하고는 항상 클래식 렌더러를 사용합니다. 다른 세션에서 `/tui fullscreen`을 실행하면 Claude Code는 전환하는 대신 설명을 출력하며 저장된 `tui` 설정을 변경하지 않습니다.

다시 시작된 세션은 화면에 보이는 대로 대화를 유지합니다. 세션 내에서 이전에 [`/rewind`](/docs/en/checkpointing#rewind-and-summarize)를 실행한 경우, 다시 시작하면 디스크에 저장된 긴 트랜스크립트 대신 되감긴 지점부터 재개됩니다. v2.1.207 이전에는 되감기 후 렌더러를 전환하면 되감기로 제거된 대화가 복원되었습니다.

Claude Code를 시작하기 전에 `CLAUDE_CODE_NO_FLICKER` 환경 변수를 설정할 수도 있습니다.

```bash theme={null}
CLAUDE_CODE_NO_FLICKER=1 claude
```

`tui` 설정과 환경 변수는 동일합니다. `/tui` 명령은 다시 시작된 프로세스에서 `CLAUDE_CODE_NO_FLICKER`를 지우므로 작성한 설정이 적용됩니다.

## 변경되는 사항

전체 화면 렌더링은 CLI가 터미널에 그리는 방식을 변경합니다. 입력을 마치는 상자가 출력이 스트리밍됨에 따라 이동하는 대신 화면 하단에 고정됩니다. Claude가 작업하는 동안 입력 상자가 움직이지 않는다면 전체 화면 렌더링이 활성화된 것입니다. 렌더 트리에 보이는 메시지만 유지되므로 대화 길이에 관계없이 메모리가 일정하게 유지됩니다.

대화가 터미널의 스크롤백이 아닌 대안 화면 버퍼에 존재하므로 몇 가지 사항이 다르게 작동합니다.

| 이전 | 현재 | 세부 정보 |
| :--- | :--- | :--- |
| `Cmd+f` 또는 tmux 검색으로 텍스트 찾기 | `Ctrl+o`로 트랜스크립트 모드 진입 후 `/`로 검색 또는 `[`로 스크롤백에 쓰기 | [대화 검색 및 검토](#search-and-review-the-conversation) |
| 터미널 자체 드래그 앤 드롭으로 선택 및 복사 | 앱 내 선택, 마우스 버튼을 떼면 자동 복사 | [마우스 사용하기](#use-the-mouse) |
| `Cmd`-클릭으로 URL 열기 | macOS에서는 `Cmd`-클릭, 다른 플랫폼에서는 `Ctrl`-클릭 | [마우스 사용하기](#use-the-mouse) |

마우스 캡처가 워크플로우를 방해하는 경우 깜빡임 없는 렌더링을 유지하면서 [마우스 캡처를 끌 수 있습니다](#keep-native-text-selection).

## 마우스 사용하기

전체 화면 렌더링은 마우스 이벤트를 캡처하여 Claude Code 내부에서 처리합니다.

* **프롬프트 입력창 클릭**: 입력 중인 텍스트의 원하는 위치에 커서를 놓습니다.
* **`/` 명령 또는 `@` 파일 목록에서 제안 클릭**: 제안을 수락합니다. 마우스를 올리면 커서 아래의 행이 하이라이트됩니다.
* **선택 메뉴의 옵션 클릭**: 옵션을 선택합니다. 권한 프롬프트, `/model`, `/config` 및 옵션 목록을 표시하는 기타 다이얼로그에 적용됩니다. 마우스를 올리면 커서 아래 행에 포인터가 표시됩니다. {/* min-version: 2.1.187 */}Claude Code v2.1.187 이상이 필요합니다.
* **다중 선택 메뉴의 옵션 클릭**: 토글하며 제출 버튼을 클릭하여 선택을 확정합니다. 객관식 질문의 `Other` 행과 같이 자유 텍스트 행을 클릭하면 입력 필드에 포커스가 맞춰져 답변을 입력할 수 있습니다. {/* min-version: 2.1.208 */}Claude Code v2.1.208 이상이 필요합니다.
* **접힌 도구 결과 클릭**: 결과를 펼쳐 전체 출력을 확인합니다. 다시 클릭하면 접힙니다. 도구 호출과 결과가 함께 펼쳐집니다. 볼 내용이 더 있는 메시지만 클릭할 수 있습니다.
* **macOS에서는 `Cmd`, Linux 및 Windows에서는 `Ctrl`을 누른 채 URL이나 파일 경로 클릭**: 해당 대상을 엽니다. Edit 또는 Write 후에 출력되는 파일 경로는 기본 애플리케이션에서 열립니다. 일반 `http://` 및 `https://` URL은 브라우저에서 열립니다. {/* min-version: 2.1.181 */}v2.1.181부터 `Cmd` 또는 `Ctrl`을 누르지 않은 일반 클릭은 링크를 열지 않아 터미널 기본 동작과 일치합니다. 일부 macOS 터미널은 `Cmd`+클릭을 스스로 처리하는 대신 실행 중인 앱으로 전달하며, 터미널 마우스 프로토콜은 `Cmd` 키를 인코딩할 방법이 없어 Claude Code가 이를 일반 클릭으로 수신합니다. Ghostty 및 macOS Warp(v2.1.198부터)에서는 Claude Code가 이를 감지하여 링크를 일반 클릭으로 열 수 있게 하며 `Cmd` 누르기도 여전히 작동합니다. VS Code 통합 터미널 및 유사한 xterm.js 기반 터미널에서는 동일한 제스처를 사용하는 터미널 자체 링크 핸들러에 위임합니다.
* **클릭 후 드래그**: 대화 내 임의의 위치에서 텍스트를 선택합니다. 더블 클릭은 단어를 선택하며, iTerm2의 단어 경계와 일치하여 파일 경로가 하나의 단위로 선택됩니다. {/* min-version: 2.1.198 */}v2.1.198부터 URL을 더블 클릭하면 스킴을 포함한 전체 URL이 선택됩니다. 트리플 클릭은 줄 전체를 선택합니다.
* **마우스 휠 스크롤**: 대화를 스크롤합니다.

선택한 텍스트는 마우스 버튼을 떼면 클립보드로 자동 복사됩니다. 이를 끄려면 `/config`에서 Copy on select를 토글하세요.

Copy on select가 꺼진 상태에서는 `Ctrl+Shift+c`를 눌러 수동으로 복사하세요. kitty, WezTerm, Ghostty, iTerm2와 같이 kitty 키보드 프로토콜을 지원하는 터미널에서는 `Cmd+c`도 작동합니다. 선택 영역이 활성화되어 있으면 `Ctrl+c`가 취소 대신 복사를 수행합니다.

선택 영역이 활성화된 상태에서 `Shift`를 누른 채 화살표 키를 누르면 키보드로 영역을 확장할 수 있습니다. 선택 영역이 상단 또는 하단 가장자리에 도달하면 `Shift+↑` 및 `Shift+↓`가 뷰포트를 스크롤합니다. `Shift+Home` 및 `Shift+End`는 현재 줄의 시작이나 끝으로 확장합니다.

## 대화 스크롤하기

전체 화면 렌더링은 앱 내부에서 스크롤을 처리합니다. 이동하려면 다음 단축키를 사용하세요.

| 단축키 | 동작 |
| :--- | :--- |
| `PgUp` / `PgDn` | 반 화면씩 위 또는 아래로 스크롤 |
| `Ctrl+Home` | 대화 시작 위치로 이동 |
| `Ctrl+End` | 가장 최근 메시지로 이동하고 자동 팔로우 재활성화 |
| 마우스 휠 | 한 번에 몇 줄씩 스크롤 |

MacBook 키보드와 같이 전용 `PgUp`, `PgDn`, `Home`, `End` 키가 없는 키보드에서는 화살표 키와 함께 `Fn`을 누르세요: `Fn+↑`는 `PgUp`, `Fn+↓`는 `PgDn`, `Fn+←`는 `Home`, `Fn+→`는 `End`를 보냅니다. macOS에서 `Ctrl+Fn+→`는 Claude Code에 도달하지 않으므로 MacBook 키보드에는 기본적으로 작동하는 맨 아래로 이동 조합이 없습니다. 대신 다음 옵션 중 하나를 사용하세요.

* [맨 아래로 이동 버튼](#auto-follow)을 클릭하세요.
* 마우스 휠로 맨 아래까지 스크롤하여 팔로우를 재개하세요.
* 키보드가 보낼 수 있는 조합으로 `scroll:bottom`을 다시 바인딩하세요.

이러한 동작은 재바인딩이 가능합니다. 기본 바인딩이 없는 반 페이지 및 전체 페이지 변형을 포함한 전체 동작 이름 목록은 [스크롤 동작](/docs/en/keybindings#scroll-actions)을 참조하세요.

### 자동 팔로우 (Auto-follow)

위로 스크롤하면 자동 팔로우가 일시 중지되어 새 출력이 아래로 끌어당기지 않습니다. 위로 스크롤되어 있는 동안 트랜스크립트 하단 가장자리 위에 `Jump to bottom` 버튼이 떠 있으며, 새 출력이 도착하면 `3 new messages`와 같이 카운트를 표시합니다. 버튼을 클릭하거나 `Ctrl+End`를 누르거나 맨 아래로 스크롤하여 팔로우를 재개하세요.

자동 팔로우가 일시 중지되어 있는 동안 응답 스트리밍이 끝나더라도 뷰는 스크롤한 위치에 그대로 유지됩니다. v2.1.207 이전에는 긴 응답 스트리밍이 끝나면 뷰가 답변 시작 위치 위로 튀는 현상이 있었습니다.

버튼의 키보드 힌트는 키보드가 보낼 수 있는 신호를 반영합니다. macOS에서는 Mac 키보드에서 `Ctrl+End`가 Claude Code에 도달하지 않기 때문에 클릭하거나 `Fn+↓`를 눌러 스크롤하도록 제안합니다. [`scroll:bottom`](/docs/en/keybindings#scroll-actions)을 다시 바인딩하면 모든 플랫폼에서 해당 바인딩이 버튼에 표시됩니다. v2.1.206 이전에는 macOS에서도 `Ctrl+End`를 제안했습니다.

전체 라벨을 표시하기에 터미널 폭이 너무 좁은 경우 버튼은 아래 트랜스크립트 줄로 줄바꿈되는 대신 힌트를 줄여서 표시합니다. v2.1.206 이전에는 긴 라벨이 트랜스크립트 위로 줄바꿈될 수 있었습니다.

자동 팔로우를 완전히 꺼서 뷰가 놓은 위치에 그대로 유지되도록 하려면 `/config`를 열고 Auto-scroll을 off로 설정하세요. 자동 스크롤이 비활성화되면 이 설정과 관계없이 뷰가 스스로 맨 아래로 튀지 않습니다. 응답이 필요한 권한 프롬프트나 기타 다이얼로그는 이 설정과 관계없이 뷰에 스크롤되어 나타납니다.

### 마우스 휠 스크롤

마우스 휠 스크롤은 터미널이 마우스 이벤트를 Claude Code로 전달해야 합니다. 대부분의 터미널은 애플리케이션이 요청할 때 이를 수행합니다. iTerm2는 이를 프로필별 설정으로 처리합니다: 휠이 작동하지 않고 `PgUp` 및 `PgDn`만 작동하는 경우 Settings → Profiles → Terminal을 열고 Enable mouse reporting을 켜세요. 클릭하여 펼치기 및 텍스트 선택이 작동하려면 동일한 설정이 필요합니다.

마우스 휠 스크롤이 느리게 느껴진다면 터미널이 배율 없이 물리적 틱당 하나의 스크롤 이벤트만 전송하기 때문일 수 있습니다. Ghostty 및 빠른 스크롤이 활성화된 iTerm2와 같은 일부 터미널은 이미 휠 이벤트를 증폭합니다. VS Code 통합 터미널을 포함한 다른 터미널은 틱당 정확히 하나의 이벤트를 보냅니다. Claude Code는 이를 감지할 수 없습니다.

기본 스크롤 거리를 배가하려면 `CLAUDE_CODE_SCROLL_SPEED`를 설정하세요.

```bash theme={null}
export CLAUDE_CODE_SCROLL_SPEED=3
```

`3` 값은 `vim` 및 유사한 애플리케이션의 기본값과 일치합니다. 설정은 이미 휠 이벤트를 증폭하는 터미널에서 가속된 트랙패드 및 휠 스크롤을 늦추기 위해 `0.25`와 같은 1 미만의 소수를 포함하여 최대 20까지의 양수 값을 허용합니다.

스크롤 속도를 대화형으로 조정하려면 `/scroll-speed`를 실행하세요. 열려 있는 동안 자를 스크롤하여 변경 사항을 즉시 느낄 수 있습니다. `←` 및 `→`를 눌러 속도를 조정하고, `r`을 눌러 자동 감지된 기본값으로 재설정하며, `Enter`를 눌러 저장하세요. 다이얼로그는 10까지의 정수로 조정할 수 있으며, 더 미세한 제어를 지원하는 터미널에서는 0.25까지의 쿼터 단계도 제공합니다. {/* min-version: 2.1.172 */}쿼터 단계에는 Claude Code v2.1.172 이상이 필요합니다.

이 명령은 `CLAUDE_CODE_SCROLL_SPEED` 환경 변수가 설정하는 것과 동일한 값을 `~/.claude/settings.json`에 저장합니다. 다이얼로그의 최대값은 10입니다: 환경 변수를 통해 더 높은 값을 설정하더라도 다이얼로그에는 10이 표시되며 다이얼로그에서 저장하면 10이 유지됩니다. 이 명령은 JetBrains IDE 터미널에서는 사용할 수 없습니다.

기본 속도와 별개로 Claude Code는 휠을 빠르게 돌릴 때 스크롤 속도를 가속하여 빠른 회전이 동일한 수의 느린 틱보다 더 많은 거리를 이동하도록 합니다. {/* min-version: 2.1.174 */}가속을 끄고 틱당 일정 비율을 유지하려면 [`settings.json`](/docs/en/settings#available-settings)에서 `wheelScrollAccelerationEnabled`를 `false`로 설정하세요. 이 설정에는 Claude Code v2.1.174 이상이 필요합니다.

### JetBrains IDE 터미널에서 스크롤

JetBrains IDE 터미널에서 Claude Code는 자체 스크롤 처리를 적용하고 `CLAUDE_CODE_SCROLL_SPEED`를 무시합니다. 해당 터미널은 다른 에뮬레이터보다 훨씬 높은 빈도로 스크롤 이벤트를 보내므로 다른 곳에 맞춘 배율은 여기서 너무 크게 지나치게 됩니다.

2025.2 버전에서 터미널에는 잘못된 화살표 키와 잘못된 방향 이벤트를 생성하는 마우스 휠 버그가 있습니다. Claude Code는 런타임에 이를 감지하고 자동으로 완화하므로 트랙패드 및 마우스 휠 스크롤이 설정 없이 작동합니다. 최상의 스크롤 환경을 위해 2025.3 이상으로 업그레이드하세요. Claude Code는 버그를 감지하면 처음 스크롤할 때 힌트를 표시합니다.

## 대화 검색 및 검토

`Ctrl+o`는 일반 프롬프트와 트랜스크립트 모드 간을 토글합니다.

마지막 프롬프트, 편집 diffstat이 포함된 도구 호출의 한 줄 요약, 최종 응답만 보여주는 더 조용한 뷰를 원하면 `/focus`를 실행하세요. 이 설정은 세션 전반으로 유지됩니다. 끄려면 `/focus`를 다시 실행하세요.

트랜스크립트 모드는 `less` 스타일의 탐색 및 검색 기능을 제공합니다.

| 키 | 동작 |
| :--- | :--- |
| `/` | 검색 열기. 입력하여 일치 항목 찾기, `Enter`로 수락, `Esc`로 취소 및 스크롤 위치 복원 |
| `n` / `N` | 다음 또는 이전 일치 항목으로 이동. 검색창을 닫은 후에도 작동 |
| `j` / `k` 또는 `↑` / `↓` | 한 줄 스크롤 |
| `g` / `G` 또는 `Home` / `End` | 맨 위 또는 맨 아래로 이동 |
| `{` / `}` | 이전 또는 다음 프롬프트로 이동 |
| `Ctrl+u` / `Ctrl+d` | 반 페이지 스크롤 |
| `Ctrl+b` / `Ctrl+f` 또는 `Space` / `b` | 전체 페이지 스크롤 |
| `Ctrl+o`, `Esc`, 또는 `q` | 트랜스크립트 모드를 종료하고 프롬프트로 복귀 |

터미널의 `Cmd+f` 및 tmux 검색은 대화 내용이 기본 스크롤백이 아닌 대안 화면 버퍼에 존재하므로 대화를 볼 수 없습니다. 내용을 다시 터미널에 전달하려면 먼저 `Ctrl+o`를 눌러 트랜스크립트 모드로 진입한 후:

* **`[`**: 모든 도구 출력이 펼쳐진 상태로 전체 대화를 터미널의 기본 스크롤백 버퍼에 씁니다. 이제 대화가 터미널의 일반 텍스트가 되므로 `Cmd+f`, tmux 복사 모드 및 기타 원시 도구로 검색하거나 선택할 수 있습니다. 긴 세션의 경우 이 작업이 진행되는 동안 잠시 정지될 수 있습니다. 이는 `Esc` 또는 `q`로 트랜스크립트 모드를 종료하여 전체 화면 렌더링으로 돌아갈 때까지 유지됩니다. 다음 `Ctrl+o`는 새로 시작됩니다.
* **`v`**: 대화를 임시 파일에 쓰고 `$VISUAL` 또는 `$EDITOR`에서 엽니다.

`Esc` 또는 `q`를 눌러 프롬프트로 복귀하세요.

## 대화 지우기

2초 이내에 `Ctrl+L`을 두 번 눌러 `/clear`를 실행하고 새 대화를 시작하세요. 첫 번째 누름은 화면을 다시 그리고 힌트를 표시하며, 두 번째 누름은 대화를 지웁니다. macOS에서는 `Cmd+K`를 두 번 누르는 것으로도 `/clear`가 실행됩니다.

## tmux와 함께 사용하기

전체 화면 렌더링은 세 가지 주의 사항을 제외하고 tmux 내부에서 작동합니다.

마우스 휠 스크롤을 사용하려면 tmux의 마우스 모드가 필요합니다. `~/.tmux.conf`에서 이미 활성화되어 있지 않다면 다음 줄을 추가하고 설정을 다시 로드하세요.

```bash theme={null}
set -g mouse on
```

마우스 모드가 없으면 휠 이벤트가 Claude Code 대신 tmux로 전달됩니다. `PgUp` 및 `PgDn`을 이용한 키보드 스크롤은 어느 쪽이든 작동합니다. Claude Code는 마우스 모드가 꺼진 tmux를 감지하면 시작 시 일회성 힌트를 출력합니다.

전체 화면 렌더링은 `tmux -CC`로 진입하는 모드인 iTerm2의 tmux 통합 모드와 호환되지 않습니다. 통합 모드에서 iTerm2는 tmux가 터미널에 그리도록 허용하는 대신 각 tmux 창을 기본 분할 화면으로 렌더링합니다. 대안 화면 버퍼와 마우스 추적은 거기서 올바르게 작동하지 않습니다: 마우스 휠이 작동하지 않으며 더블 클릭이 터미널 상태를 손상시킬 수 있습니다. `tmux -CC` 세션에서는 전체 화면 렌더링을 활성화하지 마세요. `-CC`가 없는 일반 tmux는 iTerm2 내부에서 잘 작동합니다.

3.6 시리즈 이하의 tmux 릴리스는 동기화된 출력(synchronized output)을 구현하지 않으므로 해당 버전에서는 터미널에서 Claude Code를 직접 실행할 때보다 다시 그리는 동안 깜빡임이 더 많이 발생할 수 있습니다. Claude Code는 시작 시 동기화된 출력 지원 여부를 프로브하고 터미널이 보고할 때 이를 사용합니다. tmux에서 깜빡임이 보이면 최신 tmux로 업그레이드하거나 tmux 외부의 자체 터미널 탭에서 Claude Code를 실행하세요.

## 기본 텍스트 선택 유지하기

마우스 캡처는 특히 SSH나 tmux 내부에서 가장 흔한 마찰 지점입니다. Claude Code가 마우스 이벤트를 캡처하면 터미널의 기본 선택 시 자동 복사가 작동하지 않습니다. 드래그 앤 드롭으로 만든 선택 영역은 터미널의 선택 버퍼가 아닌 Claude Code 내부 존재하므로 tmux 복사 모드, Kitty 힌트 및 유사한 도구가 이를 보지 못합니다.

Claude Code는 선택 영역을 시스템 클립보드에 쓰며, 사용하는 경로는 설정에 따라 다릅니다. 로컬 세션에서는 기본 클립보드 도구를 실행합니다.

* **macOS**: `pbcopy`
* **Linux**: Wayland의 경우 `wl-copy`, X11의 경우 `xclip` 또는 `xsel`(설치된 쪽). Claude Code는 클립보드와 PRIMARY 선택 영역 모두에 쓰므로 휠 클릭 붙여넣기가 작동합니다.
* **Windows 및 WSL**: PowerShell `Set-Clipboard`

tmux 내부에서는 tmux 붙여넣기 버퍼에도 씁니다. SSH에서는 OSC 52 이스케이프 시퀀스로 폴백합니다. Claude Code는 복사할 때마다 사용한 경로를 알려주는 토스트 메시지를 출력합니다.

일부 터미널은 기본적으로 OSC 52를 차단합니다. iTerm2는 Settings → General → Selection → Applications in terminal may access clipboard를 켤 때까지 이를 차단합니다; iTerm2에서 [`/terminal-setup`](/docs/en/terminal-config)을 실행하면 이 기능이 활성화됩니다.

일회성 기본 선택의 경우 사용할 키는 터미널에 따라 다릅니다.

* **Terminal.app**: `Fn`
* **iTerm2**: `Option`
* **VS Code, Cursor 및 Devin Desktop**: `Shift`, 또는 macOS에서 `terminal.integrated.macOptionClickForcesSelection` 설정이 활성화된 경우 `Option`
* **대부분의 기타 터미널**: `Shift`

클릭하고 드래그하는 동안 해당 키를 누르고 계세요. 터미널이 선택 영역을 Claude Code로 전달하는 대신 직접 처리하므로 `Cmd+C`와 같은 복사 단축키가 선택한 영역에서 작동합니다. Claude Code는 화면 힌트에도 올바른 키를 표시합니다.

SSH 또는 tmux 내부에서 Claude Code는 연결 중인 터미널을 항상 감지할 수 있는 것은 아니므로 힌트에 후보 키를 나열합니다.

항상 기본 선택에 의존하는 경우 `CLAUDE_CODE_DISABLE_MOUSE=1`을 설정하여 깜빡임 없는 렌더링과 일정한 메모리를 유지하면서 마우스 캡처를 옵트아웃하세요.

```bash theme={null}
CLAUDE_CODE_NO_FLICKER=1 CLAUDE_CODE_DISABLE_MOUSE=1 claude
```

마우스 캡처가 비활성화되어도 `PgUp`, `PgDn`, `Ctrl+Home`, `Ctrl+End`를 이용한 키보드 스크롤은 여전히 작동하며 터미널이 선택 영역을 기본적으로 처리합니다. Claude Code 내부에서 커서 위치 지정을 위한 클릭, 도구 출력 펼치기 클릭, URL 클릭, 휠 스크롤 기능은 손실됩니다.

휠 스크롤은 유지하되 클릭, 드래그 및 호버 처리를 끄려면 대신 `CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1`을 설정하세요. Claude Code v2.1.195 이상이 필요합니다. 두 변수가 모두 설정된 경우 `CLAUDE_CODE_DISABLE_MOUSE`가 우선합니다.

클릭이 비활성화되면 Claude Code가 마우스를 계속 캡처하므로 휠과 터치패드가 대화를 스크롤하지만 왼쪽 클릭은 Claude Code 내부에서 아무것도 하지 않습니다. 기본 드래그 앤 드롭 선택 영역을 위해 터미널 키를 계속 누르고 있어야 합니다. 우클릭 및 휠 클릭 붙여넣기는 이를 지원하는 터미널에서 계속 작동합니다.

## 문제 해결

### 화면에 이전 텍스트가 남아 있거나 위치가 어긋나는 경우

전체 화면 렌더링은 프레임 간에 변경된 셀만 전송합니다. 가장 흔하게 Windows Terminal 및 기타 ConPTY 기반 호스트와 같은 일부 터미널은 이러한 위치 지정 쓰기를 잘못 합쳐 창 크기를 조정할 때까지 이전 출력의 파편을 화면에 남깁니다.

인크리멘탈 업데이트를 보내는 대신 매 프레임마다 모든 셀을 다시 그리려면 [`CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1`](/docs/en/env-vars)을 설정하세요.

Windows PowerShell에서:

```powershell theme={null}
$env:CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT = "1"
claude
```

macOS 또는 Linux에서:

```bash theme={null}
CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1 claude
```

Windows에서 Claude Code는 백그라운드 세션 및 [에이전트 뷰](/docs/en/agent-view)에 대해 이미 전체 다시 그리기를 자동으로 활성화하므로 직접 시작한 대화형 전체 화면 세션에 대해서만 이 변수를 설정하면 됩니다.

## 리서치 프리뷰 안내

전체 화면 렌더링은 리서치 프리뷰 기능입니다. 일반적인 터미널 에뮬레이터에서 테스트되었으나 흔하지 않은 터미널이나 특이한 구성에서는 렌더링 문제가 발생할 수 있습니다.

문제가 발생하면 Claude Code 내부에서 `/feedback`을 실행하여 보고하거나 [claude-code GitHub 리포지토리](https://github.com/anthropics/claude-code/issues)에 이슈를 열어 주세요. 터미널 에뮬레이터 이름과 버전을 포함해 주세요.

전체 화면 렌더링을 끄려면 `/tui default`를 실행하거나 해당 방식으로 활성화한 경우 `CLAUDE_CODE_NO_FLICKER`를 해제하세요. `/tui default`로 다시 전환할 때 Claude Code는 전환한 이유를 묻는 선택적 피드백 프롬프트를 먼저 표시할 수 있습니다. 이유를 입력하고 `Enter`를 눌러 전송하거나 `Esc`를 눌러 건너뛰세요. 어느 쪽이든 CLI는 클래식 렌더러로 다시 시작됩니다. 저장된 `tui` 설정과 관계없이 강제로 클래식 렌더러를 사용하려면 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`을 설정하세요. 클래식 렌더러는 대화를 터미널의 기본 스크롤백에 유지하므로 `Cmd+f` 및 tmux 복사 모드가 평소대로 작동합니다.

[에이전트 뷰](/docs/en/agent-view) 또는 `claude attach`에서 연 백그라운드 세션은 항상 전체 화면 렌더링을 사용합니다. 연결하는 터미널은 세션을 표시하기 위해 대안 화면 버퍼로 진입하며 클래식 렌더러는 거기서 스크롤백이나 마우스 처리가 없으므로 `tui` 설정 및 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN`이 적용되지 않습니다.

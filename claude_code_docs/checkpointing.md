# 체크포인팅 (Checkpointing)

> Claude의 편집 내역 및 대화를 추적, 되돌리기(rewind), 요약하여 세션 상태를 관리하세요.

Claude Code는 작업 중에 Claude의 파일 편집 내역을 자동으로 추적하므로 작업이 잘못 진행되더라도 변경 사항을 빠르게 취소하고 이전 상태로 되돌릴 수 있습니다.

## 체크포인트 작동 방식

Claude와 작업할 때 체크포인팅 기능은 각 사용자 프롬프트 전의 코드 상태를 자동으로 캡처합니다. 이러한 안전장치를 통해 언제든지 이전 코드 상태로 돌아갈 수 있음을 확인하고 야심 찬 대규모 작업을 진행할 수 있습니다.

### 자동 추적

Claude Code는 파일 편집 도구로 만든 모든 변경 사항을 추적합니다:

* 모든 사용자 프롬프트는 새로운 체크포인트를 생성합니다.
* Claude Code는 세션에서 가장 최근의 100개 체크포인트에 대한 파일 스냅샷을 유지합니다. 이전 체크포인트를 폐기하면, VS Code 확장 프로그램이 세션 차이점(diff)의 기준선으로 사용하는 각 파일의 첫 번째 스냅샷을 제외하고 남아있는 체크포인트에서 참조하지 않는 스냅샷 파일이 삭제됩니다. {/* min-version: 2.1.208 */}v2.1.208 이전에는 대체된 스냅샷 파일이 세션이 정리될 때까지 디스크에 유지되었습니다.
* 체크포인트는 대화와 함께 저장되므로 재개된 세션에서도 여전히 해당 체크포인트로 `/rewind`할 수 있습니다.
* 세션과 함께 30일 후에 자동으로 정리되며, [`cleanupPeriodDays`](/docs/en/settings#available-settings)를 통해 설정할 수 있습니다.

### 되돌리기 및 요약 (Rewind and summarize)

`/rewind`를 실행하거나 프롬프트 입력창이 비어 있을 때 `Esc` 키를 두 번 눌러 되돌리기 메뉴를 엽니다.

<Note>
  프롬프트 입력창에 텍스트가 있으면 `Esc` 키를 두 번 누를 때 메뉴를 여는 대신 텍스트가 지워집니다. 지워진 텍스트는 입력 기록에 저장되므로 되돌리기 메뉴에서 작업을 마친 후 `Up` 화살표 키를 눌러 다시 불러올 수 있습니다.
</Note>

되돌리기 메뉴에는 세션 중에 전송한 각 프롬프트가 나열됩니다. 조치를 취할 지점을 선택한 다음 작업 옵션을 선택하세요:

* **Restore code and conversation**: 코드와 대화 모두 해당 지점으로 복원
* **Restore conversation**: 현재 코드는 유지하면서 해당 메시지로 대화 되돌리기
* **Restore code**: 대화는 유지하면서 파일 변경 사항 되돌리기
* **Summarize from here**: 이 지점부터의 대화를 요약으로 압축하여 컨텍스트 창 공간 확보
* **Summarize up to here**: 이 지점 이전의 대화를 요약으로 압축하고 이후 메시지는 그대로 유지
* **Never mind**: 변경 없이 메시지 목록으로 돌아가기

두 가지 코드 복원 옵션은 선택한 체크포인트에 되돌릴 추적된 파일 변경 사항이 있을 때만 표시됩니다. 해당 지점 이후에 캡처된 파일 편집이 없으면 메뉴에는 **Restore conversation**, 요약 옵션들, **Never mind**만 제공됩니다.

대화를 복원하거나 "Summarize from here"를 선택한 후, 선택한 메시지의 원래 프롬프트가 입력 필드에 복원되므로 이를 재전송하거나 편집할 수 있습니다.

"Summarize up to here"를 선택하면 입력 창이 비어 있는 상태로 대화의 끝에 위치하게 됩니다. 두 요약 옵션 중 하나를 선택하면 압축된 메시지가 있던 대화 위치에 **Summarized conversation** 마커가 나타납니다.

#### 지워진 대화 너머로 되돌리기

동일한 Claude Code 프로세스에서 이전에 `/clear`를 실행한 경우, 되돌리기 메뉴의 목록 맨 위에 `/resume <session-id> (previous session)`으로 레이블이 지정된 추가 항목이 표시됩니다. 이를 선택하면 `/clear`가 실행되기 전에 활성화되었던 대화를 재개할 수 있습니다. 이 항목은 Claude Code를 종료하거나 다른 세션을 재개할 때까지 사용할 수 있으며 Claude Code v2.1.191 이상이 필요합니다. 이전 버전에서는 `/resume`를 실행하고 목록에서 이전 세션을 선택하세요.

#### 복원 vs 요약

복원 옵션은 상태를 되돌립니다: 코드 변경 사항, 대화 기록 또는 둘 다를 취소합니다. 요약 옵션은 디스크의 파일을 변경하지 않고 대화의 일부를 AI 생성 요약으로 압축합니다:

* **Summarize from here**: 선택한 메시지 이전의 메시지는 그대로 유지됩니다. 선택한 메시지와 그 이후의 모든 메시지는 요약으로 대체됩니다. 이 기능은 초기 컨텍스트를 전체 세부 정보로 유지하면서 대화의 지류(side discussion)를 삭제할 때 사용합니다.
* **Summarize up to here**: 선택한 메시지 이전의 메시지가 요약으로 대체됩니다. 선택한 메시지와 그 이후의 모든 메시지는 그대로 유지되며 대화의 끝에 유지됩니다. 이 기능은 최근 작업을 전체 세부 정보로 유지하면서 초기 설정 관련 대화를 압축할 때 사용합니다.

두 경우 모두 원래 메시지는 세션 트랜스크립트에 보존되므로 필요한 경우 Claude가 세부 사항을 참조할 수 있습니다. 요약이 집중할 내용을 안내하려면 화살표 키로 **Summarize** 옵션을 강조 표시하고 행에 **add context (optional)**이라고 표시된 위치에 인라인으로 지침을 입력한 다음 `Enter` 키를 눌러 요약하세요. 숫자 키로 옵션을 선택하면 지침 없이 즉시 요약됩니다. 이는 `/compact`와 유사하지만 대상이 지정됩니다. 즉, 전체 대화를 요약하는 대신 선택한 메시지의 어느 쪽을 압축할지 선택합니다.

<Note>
  요약은 동일한 세션을 유지하면서 컨텍스트를 압축합니다. 원래 세션을 그대로 보존하면서 분기하여 다른 접근 방식을 시도하려면 대신 [`/branch`](/docs/en/sessions#branch-a-session) 또는 `claude --continue --fork-session`을 사용하세요.
</Note>

## 주요 사용 사례

체크포인트는 다음과 같은 경우에 특히 유용합니다:

* **대안 탐색**: 시작 지점을 잃지 않고 다양한 구현 접근 방식 시도
* **실수 복구**: 버그를 유발하거나 기능을 손상시킨 변경 사항을 빠르게 취소
* **기능 반복 시도**: 작동하는 상태로 되돌릴 수 있음을 확인하고 여러 변형 실험
* **컨텍스트 공간 확보**: 디버깅 세션 중간부터 지류 대화를 요약하여 초기 지시사항을 손상 없이 유지

## 제약 사항

### Bash 명령 변경 사항은 추적되지 않음

체크포인팅은 bash 명령에 의해 수정된 파일을 추적하지 않습니다. 예를 들어 Claude Code가 다음을 실행하는 경우:

```bash theme={null}
rm file.txt
mv old.txt new.txt
cp source.txt dest.txt
```

이러한 파일 수정 사항은되돌리기(rewind)를 통해 취소할 수 없습니다. Claude의 파일 편집 도구를 통해 직접 수행된 파일 편집만 추적됩니다.

### 외부 변경 사항은 추적되지 않음

체크포인팅은 현재 세션 내에서 편집된 파일만 추적합니다. Claude Code 외부에서 파일에 수동으로 가한 변경 사항 및 동시 실행 중인 다른 세션에서의 편집 사항은 현재 세션과 동일한 파일을 수정하게 되는 경우를 제외하고는 일반적으로 캡처되지 않습니다.

### 심볼릭 링크 및 하드 링크 경로는 복원되지 않음

체크포인팅은 심볼릭 링크나 하드 링크 파일을 되돌리지 않습니다. `/rewind` 메뉴에서 **Restore code** 또는 **Restore code and conversation**을 선택할 때 Claude Code는 심볼릭 링크 또는 하드 링크인 추적된 경로를 건너뛰고 `Restored the code, but skipped N files` 경고를 표시합니다. 건너뛴 파일은 현재 내용을 유지합니다. 이러한 파일 중 하나에 대한 세션의 변경 사항을 취소하려면 Claude에게 편집을 취소하도록 요청하거나 파일 직접 편집하세요. 닷파일 관리자가 프로젝트에 심볼릭 링크한 설정 파일과 pnpm이 해당 위치에 하드 링크한 파일이 모두 이 범주에 속합니다.

복원 시 건너뛰는 경로를 확인하려면 복원하기 전에 `/debug`로 디버그 로깅을 켜세요. `~/.claude/debug/<session-id>.txt`의 디버그 로그에 건너뛴 각 경로 이름이 지정됩니다. 모든 건너뛰기 이유 및 복구 단계는 [오류 참조의 건너뛴 파일 항목](/docs/en/errors#restored-the-code-but-skipped-files)을 참조하세요.

<Note>
  v2.1.216 이전에는 `/rewind`가 경고 없이 추적된 경로의 링크를 통해 쓰고 삭제했습니다.
</Note>

### 버전 제어를 대체하지 않음

체크포인트는 세션 수준의 빠른 복구를 위해 설계되었습니다. 영구 버전 기록 및 협업을 위해:

* 커밋, 브랜치 및 장기 기록을 위해 버전 제어(예: Git)를 계속 사용하세요.
* 체크포인트는 적절한 버전 제어를 보완하지만 대체하지는 않습니다.
* 체크포인트를 "로컬 취소(local undo)"로 생각하고 Git을 "영구 기록(permanent history)"으로 생각하세요.

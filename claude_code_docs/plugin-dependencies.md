# 플러그인 종속성 버전 제약 (Constrain plugin dependency versions)

> 플러그인 종속성에 버전 제약을 선언하고, 큐레이팅된 플러그인 세트를 하나의 설치로 번들링합니다.

플러그인은 `plugin.json` 또는 마켓플레이스 항목에 나열하여 다른 플러그인에 종속될 수 있습니다. 기본적으로 종속성은 최신의 사용 가능한 버전을 추적하므로 업스트림 릴리스가 경고 없이 플러그인 아래의 종속성을 변경할 수 있습니다. 버전 제약을 사용하면 이동을 선택할 때까지 테스트된 버전 범위에 종속성을 보류할 수 있습니다.

종속성을 선언하는 플러그인을 설치하면 Claude Code가 자동으로 종속성을 확인 및 설치하고 설치 출력 끝에 추가된 종속성을 나열합니다. 나중에 종속성이 누락되면 마켓플레이스가 구성된 마켓플레이스에 이미 있는 경우 `/reload-plugins` 및 백그라운드 플러그인 자동 업데이트가 이를 다시 설치합니다. 종속 플러그인에서 `claude plugin install`을 다시 실행하거나 `claude plugin marketplace add`로 마켓플레이스를 추가하는 것도 미해결된 누락 종속성을 모두 해결합니다. 추가하지 않은 마켓플레이스의 종속성은 해결되지 않은 상태로 남습니다.

이 가이드는 `plugin.json`에서 종속성을 선언하는 플러그인 작성자와 릴리스를 태그 지정하는 마켓플레이스 유지 관리자를 위한 것입니다. 종속성이 있는 플러그인을 설치하려면 [플러그인 탐색 및 설치](/docs/en/discover-plugins)를 참조하세요. 전체 매니페스트 스키마는 [플러그인 참조](/docs/en/plugins-reference)를 참조하세요.

## 종속성 버전을 제약해야 하는 이유

두 팀이 플러그인을 게시하는 내부 마켓플레이스를 고려해 보세요. 플랫폼 팀은 비밀 백엔드를 래핑하는 MCP 서버인 `secrets-vault`를 유지 관리합니다. 배포 팀은 배포 중에 자격 증명을 가져오기 위해 `secrets-vault`를 호출하는 `deploy-kit`을 유지 관리합니다.

`deploy-kit`은 `secrets-vault` v2.1.0에 대해 테스트되었습니다. 버전 제약이 없으면 다음 번에 플랫폼 팀이 MCP 도구의 이름을 바꾸는 릴리스를 태그 지정할 때 자동 업데이트가 모든 엔지니어의 `secrets-vault`를 새 버전으로 이동하여 `deploy-kit`이 중단됩니다.

버전 제약을 사용하면 `deploy-kit`이 `~2.1.0` 범위의 `secrets-vault`가 필요함을 선언합니다. `deploy-kit`이 설치된 엔지니어는 가장 일치하는 `2.1.x` 패치를 유지합니다. 배포 팀은 더 넓은 제약 조건으로 새 `deploy-kit` 버전을 게시하여 자체 일정에 따라 업그레이드합니다.

## 버전 제약 조건으로 종속성 선언

플러그인의 `.claude-plugin/plugin.json`의 `dependencies` 배열에 종속성을 나열하세요. 각 항목은 플러그인 이름이거나 버전 제약 조건이 있는 객체입니다.

다음 매니페스트는 하나의 버전이 지정되지 않은 종속성과 하나의 제약된 종속성을 선언합니다:

```json .claude-plugin/plugin.json theme={null}
{
  "name": "deploy-kit",
  "version": "3.1.0",
  "dependencies": [
    "audit-logger",
    { "name": "secrets-vault", "version": "~2.1.0" }
  ]
}
```

항목은 위 예시의 `"audit-logger"`와 같이 플러그인 이름만 있는 단순 문자열일 수 있으며, 해당 플러그인의 마켓플레이스가 제공하는 모든 버전에 종속됩니다. 더 많은 제어를 위해 다음 필드가 있는 객체를 사용하세요:

| 필드 | 유형 | 설명 |
| :--- | :--- | :--- |
| `name` | string | 플러그인 이름. 선언하는 플러그인과 동일한 마켓플레이스 내에서 확인됩니다. 필수. |
| `version` | string | `~2.1.0`, `^2.0`, `>=1.4`, `=2.1.0`과 같은 [semver 범위](https://github.com/npm/node-semver#ranges). 종속성은 이 범위를 충족하는 가장 높게 태그 지정된 버전에서 가져옵니다. |
| `marketplace` | string | `name`을 확인할 다른 마켓플레이스. 타겟 마켓플레이스가 루트 마켓플레이스의 `marketplace.json`에 있는 [`allowCrossMarketplaceDependenciesOn`](#depend-on-a-plugin-from-another-marketplace)에 나열되지 않는 한 교차 마켓플레이스 종속성은 차단됩니다. |

`version` 필드는 캐럿, 틸드, 하이픈 및 비교자 범위를 포함하여 Node의 `semver` 패키지에서 지원하는 모든 표현식을 수용합니다. `2.0.0-beta.1`과 같은 프리릴리스 버전은 범위가 `^2.0.0-0`과 같은 프리릴리스 접미사로 선택되지 않는 한 제외됩니다.

## 팀을 위한 플러그인 번들링

필수 `name` 외에도 플러그인 매니페스트는 `dependencies` 배열만으로 구성될 수 있습니다. 이를 설치하면 모든 종속성이 함께 제공되므로 하나의 설치 뒤에 큐레이팅된 플러그인 세트를 패키징하는 방법이 됩니다.

예를 들어 플랫폼 팀은 엔지니어가 각 도구를 개별적으로 설치하는 대신 하나의 `claude plugin install`을 실행하도록 내부 마켓플레이스에 역할 전용 번들을 게시할 수 있습니다:

```json .claude-plugin/plugin.json theme={null}
{
  "name": "backend-standard",
  "version": "1.0.0",
  "description": "Standard plugin set for backend engineers",
  "dependencies": [
    "secrets-vault",
    "deploy-kit",
    { "name": "db-migrate", "version": "^3.0" },
    "oncall-runbook"
  ]
}
```

`backend-standard`를 설치하면 4개의 종속성이 모두 확인되고 설치됩니다.

나중에 표준 세트에 도구를 추가하려면 추가 종속성이 있는 새 `backend-standard` 버전을 게시하세요. Anthropic 이외의 마켓플레이스에 대해 자동 업데이트는 기본적으로 꺼져 있으므로 엔지니어는 다음 두 가지 방법 중 하나로 새 버전을 받습니다:

* `/plugin`에서 마켓플레이스에 대한 자동 업데이트를 활성화합니다. 다음 자동 업데이트는 번들을 새 버전으로 이동하고 추가된 종속성을 설치합니다.
* `claude plugin update backend-standard`를 실행한 후 `/reload-plugins`를 실행하여 새로 추가된 종속성을 설치합니다.

조직 전체에 번들을 롤아웃하려면 [관리형 설정](/docs/en/settings#enabledplugins)의 `enabledPlugins`에 번들 플러그인을 추가하세요.

## 다른 마켓플레이스의 플러그인에 종속

기본적으로 Claude Code는 이를 선언하는 플러그인과 다른 마켓플레이스에 존재하는 종속성을 자동 설치하는 것을 거부합니다. 이렇게 하면 하나의 마켓플레이스가 검토하지 않은 소스의 플러그인을 무단으로 가져오는 것을 방지할 수 있습니다.

이를 허용하려면 루트 마켓플레이스의 유지 관리자가 `marketplace.json`에 있는 `allowCrossMarketplaceDependenciesOn`에 타겟 마켓플레이스 이름을 추가합니다. 루트 마켓플레이스는 사용자가 설치하는 플러그인을 호스팅하는 마켓플레이스입니다. 허용 목록만 참조하므로 신뢰가 중간 마켓플레이스를 통해 체이닝되지 않습니다.

다음 `marketplace.json`은 `deploy-kit`이 `acme-shared`의 플러그인에 종속되는 것을 허용합니다:

```json .claude-plugin/marketplace.json theme={null}
{
  "name": "acme-tools",
  "owner": { "name": "Acme" },
  "allowCrossMarketplaceDependenciesOn": ["acme-shared"],
  "plugins": [
    {
      "name": "deploy-kit",
      "source": "./deploy-kit",
      "dependencies": [
        { "name": "audit-logger", "marketplace": "acme-shared" }
      ]
    }
  ]
}
```

필드가 없거나 타겟 마켓플레이스가 포함되어 있지 않은 경우 설치가 실패하고 설정할 필드가 이름 지정된 `cross-marketplace` 오류가 발생합니다. 사용자는 여전히 종속성을 수동으로 먼저 설치할 수 있으며, 이는 허용 목록을 변경하지 않고 제약 조건을 충족합니다.

## 버전 확인을 위해 플러그인 릴리스 태그 지정

버전 제약 조건은 마켓플레이스 리포지토리의 git 태그에 대해 확인됩니다. Claude Code가 종속성의 사용 가능한 버전을 찾으려면 업스트림 플러그인의 릴리스가 특정 명명 규칙을 사용하여 태그 지정되어야 합니다.

각 릴리스를 `{plugin-name}--v{version}`으로 태그 지정하세요. 여기서 `{version}`은 해당 커밋의 `plugin.json`에 있는 `version` 필드와 일치합니다. 플러그인 디렉터리에서 다음을 실행하세요:

```bash theme={null}
claude plugin tag --push
```

`claude plugin tag` 명령은 플러그인의 매니페스트 및 동봉된 마켓플레이스 항목에서 태그 이름을 파생합니다. 태그를 생성하기 전에 플러그인 내용을 검증하고, `plugin.json`과 마켓플레이스 항목이 버전에 동의하는지 확인하고, 플러그인 디렉터리 아래에 깨끗한 작업 트리가 필요한지 확인하며, 태그가 이미 존재하는 경우 거부합니다.

* `--push`는 태그를 `origin` 원격에 푸시하므로 리포지토리에 구성된 `origin` 원격이 필요합니다. 다른 원격에 푸시하려면 `--remote`를 전달하세요.
* 푸시가 실패하더라도 태그는 로컬에 생성되며 명령은 오류와 함께 종료됩니다.
* `--push`를 사용하면 성공적인 실행이 `Created tag secrets-vault--v2.1.0` 및 `Pushed to origin`으로 끝납니다. 여기서 마지막 줄은 푸시된 원격의 이름을 나타냅니다. `--push`가 없으면 명령은 실행할 `git push` 명령을 대신 출력합니다.
* `--dry-run`은 태그를 생성하지 않고 태그 지정될 항목을 출력합니다.

`plugin.json`과 마켓플레이스 항목을 직접 동기화 상태로 유지한다면 `git tag secrets-vault--v2.1.0`을 직접 실행하는 것도 동등합니다.

플러그인 이름 접두사를 사용하면 하나의 마켓플레이스 리포지토리가 독립적인 버전 라인을 가진 여러 플러그인을 호스팅할 수 있습니다. `--v` 구분 기호는 전체 플러그인 이름에 대한 접두사 일치로 해석되므로 하이픈이 포함된 플러그인 이름이 올바르게 처리됩니다.

`{ "name": "secrets-vault", "version": "~2.1.0" }`을 선언하는 플러그인을 설치하면 Claude Code는 마켓플레이스의 태그를 나열하고 `secrets-vault--v`로 시작하는 태그로 필터링하여 `~2.1.0`을 충족하는 가장 높은 버전을 가져옵니다. 일치하는 태그가 없으면 사용 가능한 버전을 나열하는 오류와 함께 종속 플러그인이 비활성화됩니다.

로컬 폴더 경로로 추가된 마켓플레이스는 폴더가 git 리포지토리인 경우 동일한 방식으로 태그를 확인합니다. 여기에 Claude Code v2.1.196 이상이 필요합니다. 다음 두 가지 경우 Claude Code는 폴더의 현재 내용에서 종속성을 대신 설치합니다:

* 이전 버전은 로컬 폴더 마켓플레이스에서 태그를 읽지 않으므로 해당 사본이 범위를 충족하는 경우에만 제약된 종속성이 로드됩니다.
* git 리포지토리가 아닌 로컬 폴더에는 버전에 관계없이 태그가 없습니다.

확인된 태그의 semver는 `plugin.json`의 `version`과 별도로 기록되므로 해당 커밋의 `plugin.json`에 오랜 값이 있더라도 제약 조건 검사는 실제로 가져온 태그를 사용합니다. 태그 확인 설치의 캐시 디렉터리 이름에는 12자의 커밋 SHA 접미사가 포함되므로 유지 관리자가 강제로 태그를 다른 커밋으로 이동하면 다음 설치 시 오래된 내용을 재사용하는 대신 새로운 캐시 디렉터리를 가져옵니다.

<Note>
  `npm` 마켓플레이스 소스의 경우 태그 기반 확인이 git 지원 소스에만 적용되므로 제약 조건이 가져오는 버전을 제어하지 않습니다. 제약 조건은 로드 시점에 여전히 검사되며 설치된 버전이 이를 충족하지 않으면 종속 플러그인이 `dependency-version-unsatisfied`로 비활성화됩니다.
</Note>

## 제약 조건의 상호작용 방식

설치된 여러 플러그인이 동일한 종속성을 제약하는 경우 Claude Code는 해당 범위를 교차하고 모든 범위를 충족하는 가장 높은 버전으로 종속성을 확인합니다. 아래 표는 일반적인 조합이 확인되는 방식을 보여줍니다.

| 플러그인 A 요구 사항 | 플러그인 B 요구 사항 | 결과 |
| :--- | :--- | :--- |
| `^2.0` | `>=2.1` | `2.1.0` 이상에서 가장 높은 `2.x` 태그에 하나의 설치. 두 플러그인 모두 로드됨. |
| `~2.1` | `~3.0` | 플러그인 B의 설치가 `range-conflict`로 실패함. 플러그인 A와 종속성은 그대로 유지됨. |
| `=2.1.0` | 없음 | 종속성은 `2.1.0`에 유지됨. 플러그인 A가 설치된 동안 자동 업데이트는 새 버전을 건너끎. |

자동 업데이트는 마켓플레이스의 최신 버전이 아니라 설치된 모든 플러그인의 범위를 충족하는 가장 높은 git 태그에서 제약된 종속성을 가져오므로 종속성은 허용 범위 내에서 업데이트를 계속 받습니다. 범위를 충족하는 태그가 없는 경우 자동 업데이트는 해당 종속성을 건너뛰고 제약 플러그인의 이름을 지정하여 `/plugin` 오류 탭에 건너뛰기를 나열합니다.

종속성을 제약하는 마지막 플러그인을 삭제하면 종속성이 더 이상 보류되지 않고 다음 업데이트 시 마켓플레이스 항목 추적을 재개합니다.

## 종속성이 있는 플러그인 활성화 또는 비활성화

플러그인을 활성화하면 그 종속 플러그인도 활성화되며, 활성화된 다른 플러그인이 여전히 필요한 경우 플러그인을 비활성화하는 것이 차단됩니다. 두 동작 모두 Claude Code v2.1.143 이상이 필요합니다. 이전 버전은 지정된 플러그인만 활성화하거나 비활성화하고 다음 로드 시 `dependency-unsatisfied` 오류를 표시합니다.

플러그인을 활성화하면 Claude Code는 동일한 범위에서 해당 종속성도 활성화합니다. 종속성에 자체 종속성이 있는 경우 Claude Code는 해당 종속성도 활성화합니다. 성공 메시지에는 지정한 플러그인과 함께 활성화된 기타 항목이 나열됩니다. 종속성을 활성화할 수 없는 경우 명령이 거부되고 차단 요소와 해결 방법이 표시됩니다:

| 조건 | 결과 |
| :--- | :--- |
| 종속성이 설치되어 있지 않음 | 활성화가 실패하고 누락된 각 종속성에 대해 `claude plugin install` 명령을 출력합니다. |
| 종속성이 조직의 플러그인 정책에 의해 차단됨 | 활성화가 실패하고 차단된 종속성의 이름을 지정합니다. |
| 종속성이 대상 범위보다 높은 우선순위를 가진 범위에서 `false`로 설정됨 | 활성화가 실패합니다. 해당 범위에서 종속성을 활성화하거나 `--scope`를 전달하여 거기에 작성하세요. |
| 모든 종속성이 설치되고 허용됨 | 활성화가 성공하고 대상 범위에서 아직 활성화되지 않은 플러그인 및 각 종속성에 대해 `true`를 작성합니다. |

이는 종속성이 매니페스트에서 [`defaultEnabled: false`](/docs/en/plugins-reference#default-enablement)를 설정하는 경우에도 유지됩니다. Claude Code가 이에 대해 명시적인 `true`를 작성하기 때문입니다. 설치 시에도 동일하게 적용됩니다. 활성 플러그인을 충족하기 위해 들어온 종속성은 자체 기본값에 관계없이 `true`로 설치됩니다.

플러그인을 비활성화하면 활성화된 다른 플러그인이 여전히 해당 플러그인에 종속되는 경우 Claude Code가 거부합니다. 오류는 이에 종속된 플러그인의 이름을 지정하고 요구한 명령으로 끝나는 올바른 순서로 비활성화하는 체인된 명령을 제공합니다.

예를 들어 `deploy-kit`이 `secrets-vault`에 종속되는 경우 `secrets-vault`만 비활성화하면 다음과 유사한 출력과 함께 실패합니다:

```text theme={null}
secrets-vault is still required by deploy-kit. Disable that plugin first, or
disable everything together: claude plugin disable deploy-kit@acme-tools && claude plugin disable secrets-vault@acme-tools
```

한 번에 전체 세트를 비활성화하려면 오류에서 체인된 명령을 복사하세요.

## 고립된 자동 설치 종속성 제거

자동 설치된 종속성은 설치된 플러그인을 재설치하거나 종속성을 직접 계속 사용하려는 경우에 대비해 설치한 플러그인이 삭제된 후에도 디스크에 유지됩니다. 이를 정리하려면 `claude plugin prune`을 실행하여 더 이상 이를 필요로 하는 설치된 플러그인이 없는 자동 설치 종속성을 나열하고 확인 프롬프트 후 제거하세요. 여기에 Claude Code v2.1.121 이상이 필요합니다.

```bash theme={null}
claude plugin prune
```

제거 자격이 되는 항목이 없으면 명령은 사유와 함께 `Nothing to prune`을 출력하고 종료합니다. 이는 새로 설치했을 때 예상되는 출력이며 오류가 아닙니다.

기본적으로 정리(prune)는 사용자 범위에서 작동하며 무엇이든 제거하기 전에 확인을 요청합니다:

* `--scope project` 또는 `--scope local`은 다른 범위를 타겟팅합니다.
* `--dry-run`은 아무것도 변경하지 않고 제거될 항목을 나열합니다.
* `-y`는 확인 프롬프트를 건너끕니다. stdin 또는 stdout이 터미널이 아닌 경우 `-y`를 전달하지 않는 한 정리 시 고립된 항목이 나열되고 제거 없이 종료됩니다.

삭제의 일부로 정리하려면 `claude plugin uninstall`에 `--prune`을 전달하세요. 지정된 플러그인을 제거한 후 Claude Code는 고립된 자동 설치 종속성을 스캔하고 제거합니다. 직접 설치한 플러그인은 절대 정리되지 않으며, 다른 플러그인의 `dependencies` 배열을 통해 자동으로 설치된 플러그인만 정리됩니다.

동일한 확인 동작이 적용됩니다: 프롬프트를 건너뛰려면 `-y`를 전달하세요. stdin 또는 stdout이 터미널이 아닌 경우에도 삭제가 완료되지만 정리 단계에서는 `-y`를 전달하지 않는 한 고립된 항목이 나열되고 아무것도 제거되지 않습니다.

예를 들어 `deploy-kit`을 삭제하고 남겨둔 종속성을 정리하려면:

```bash theme={null}
claude plugin uninstall deploy-kit --prune
```

## 종속성 오류 해결

종속성 문제는 이 표의 리터럴 코드가 아닌 설명 오류 메시지로 `claude plugin list` 및 `/plugin` 인터페이스에 나타납니다. Claude Code는 오류를 해결할 때까지 영향 받는 플러그인을 비활성화합니다. 아래 표에는 가장 일반적인 오류와 이를 해결하는 방법이 나열되어 있습니다.

| 오류 | 의미 | 해결 방법 |
| :--- | :--- | :--- |
| `dependency-unsatisfied` | 선언된 종속성이 설치되어 있지 않거나 설치되어 있지만 비활성화되어 있습니다. | 오류 메시지에 표시된 `claude plugin install` 명령을 실행하세요. 종속성의 마켓플레이스가 아직 구성되지 않은 경우 `claude plugin marketplace add`로 추가하면 Claude Code가 자동으로 종속성을 해결합니다. 종속성이 비활성화되어 있으면 활성화하세요. |
| `range-conflict` | 종속성에 대한 버전 요구 사항을 결합할 수 없습니다. 오류 메시지에 원인이 표시됩니다: 어떤 버전도 모든 범위를 충족하지 않거나, 범위가 유효한 semver 구문이 아니거나, 결합된 범위가 너무 복잡하여 교차할 수 없습니다. | 충돌하는 플러그인 중 하나를 삭제하거나 업데이트하고, 잘못된 `version` 문자열을 수정하고, 긴 `\|\|` 체인을 단순화하거나, 업스트림 작성자에게 제약 조건의 확장을 요청하세요. |
| `dependency-version-unsatisfied` | 설치된 종속성의 버전이 이 플러그인의 선언된 범위를 벗어납니다. | 현재 모든 제약 조건에 대해 종속성을 다시 확인하려면 `claude plugin install <dependency>@<marketplace>`를 실행하세요. |
| `no-matching-tag` | 종속성의 리포지토리에 범위를 충족하는 `{name}--v*` 태그가 없습니다. | 업스트림이 위의 규칙을 사용하여 릴리스를 태그 지정했는지 확인하거나 범위를 완화하세요. |

프로그래밍 방식으로 이러한 오류를 확인하려면 `claude plugin list --json`을 실행하세요. 문제가 있는 플러그인에는 이를 나열하는 `errors` 필드가 포함됩니다. 문제없이 로드된 플러그인은 이 필드가 생략됩니다.

# 대화형 모드 (Interactive mode)

> Claude Code 세션의 키보드 단축키, 입력 모드 및 대화형 기능에 대한 전체 레퍼런스입니다.

## 키보드 단축키

<Note>
  키보드 단축키는 플랫폼 및 터미널에 따라 다를 수 있습니다. [전체 화면 렌더링](/docs/en/fullscreen)에서는 트랜스크립트 뷰어에서 `?`를 눌러 사용 가능한 단축키를 확인하세요.

  **macOS 사용자**: Option/Alt 키 단축키(`Alt+B`, `Alt+F`, `Alt+Y`, `Alt+P`)를 사용하려면 터미널에서 Option을 Meta로 구성해야 합니다:

  * **iTerm2**: Settings → Profiles → Keys → General → Left/Right Option key를 "Esc+"로 설정
  * **Apple Terminal**: Settings → Profiles → Keyboard → "Use Option as Meta Key" 체크
  * **VS Code**: VS Code 설정에서 `"terminal.integrated.macOptionIsMeta": true` 설정

  자세한 내용은 [터미널 구성](/docs/en/terminal-config)을 참조하세요.
</Note>

## 명령어

Claude Code에서 `/`를 입력하여 사용할 수 있는 모든 명령을 보거나, `/` 뒤에 문자를 입력하여 필터링하세요. `/` 메뉴에는 호출할 수 있는 모든 것이 표시됩니다: 내장 명령, 번들 및 사용자 작성 [스킬](/docs/en/skills), [플러그인](/docs/en/plugins) 및 [MCP 서버](/docs/en/mcp#use-mcp-prompts-as-commands)가 제공하는 명령. 일부 명령은 플랫폼이나 플랜에 따라 다르므로 모든 내장 명령이 모든 사용자에게 보이는 것은 아닙니다.

[전체 화면 렌더링](/docs/en/fullscreen#use-the-mouse)에서 `/` 명령 및 `@` 파일 제안 목록은 마우스에도 반응합니다: 호버링하면 행이 강조 표시되고 클릭하면 수락됩니다.

Claude Code에 포함된 전체 명령 목록은 [명령어 레퍼런스](/docs/en/commands)를 참조하세요.

### INSERT 모드 키 시퀀스 리매핑

[`vimInsertModeRemaps`](/docs/en/settings#available-settings) 설정은 2자 INSERT 모드 시퀀스를 Escape로 매핑하므로 `jj`와 같은 매핑이 NORMAL 모드로 돌아가게 합니다. Claude Code v2.1.208 이상 필요.

다음 `~/.claude/settings.json` 예시는 vim 모드를 켜고 `jj`를 Escape로 매핑합니다:

```json theme={null}
{
  "editorMode": "vim",
  "vimInsertModeRemaps": { "jj": "<Esc>" }
}
```

각 키는 순서대로 입력된 정확히 두 개의 출력 가능한 문자이며 `"<Esc>"`가 유일하게 지원되는 대상입니다. 다른 길이나 대상을 가진 항목은 무시됩니다.

시퀀스의 첫 번째 문자를 입력하면 정상적으로 삽입됩니다. 1초 이내에 두 번째 문자를 누르면 대기 중인 문자가 제거되고 NORMAL 모드로 전환되어 입력에 두 문자 모두 남지 않습니다. 1초 창이 지나거나 다른 키가 이어지면 두 문자 모두 일반 텍스트로 남아 있으므로 두 키 사이에 일시 정지하여 시퀀스가 포함된 단어를 계속 입력할 수 있습니다.

Claude Code는 사용자 설정 파일, `--settings` 플래그 및 [관리형 설정](/docs/en/permissions#managed-settings)에서만 이 설정을 읽습니다. 프로젝트의 `.claude/settings.json` 또는 `.claude/settings.local.json`에 있는 항목은 무시되므로 체크아웃된 저장소가 키 입력을 다시 매핑할 수 없습니다.

## 명령 내역

Claude Code는 현재 세션의 명령 내역을 유지합니다:

* 입력 내역은 작업 디렉토리별로 저장됩니다
* 새 세션을 시작하기 위해 `/clear`를 실행하면 입력 내역이 초기화됩니다. 이전 세션의 대화는 보존되며 재개할 수 있습니다.
* 동일한 프롬프트를 연속으로 두 번 제출하면 하나의 내역 항목만 기록되므로 위쪽 방향키를 누르면 이전의 구별되는 프롬프트로 이동합니다.
* 위/아래 방향키를 사용하여 탐색합니다 (위의 키보드 단축키 참조)
* `!`를 통한 내역 확장은 기본적으로 비활성화되어 있습니다

### Ctrl+R을 이용한 역방향 검색

이전 명령 내역을 대화형으로 검색하려면 `Ctrl+R`을 누르세요. [전체 화면 렌더링](/docs/en/fullscreen)에서는 `Ctrl+R`이 대신 검색 대화 상자를 엽니다: 필터링할 내용을 입력하고 `Up` 및 `Down`을 눌러 일치 항목 간에 이동하며, `Ctrl+S`를 눌러 이 세션, 이 프로젝트, 모든 프로젝트로 범위를 순환합니다. `Enter` 또는 `Tab`을 눌러 프롬프트 입력에 일치 항목을 배치하거나 `Esc`를 눌러 취소하세요. 아래 단계는 기본 인라인 검색을 설명합니다:

1. **검색 시작**: 역방향 내역 검색을 활성화하려면 `Ctrl+R`을 누릅니다
2. **쿼리 입력**: 이전 명령에서 검색할 텍스트를 입력합니다. 검색어는 일치 결과에서 강조 표시됩니다
3. **일치 항목 탐색**: 더 오래된 일치 항목을 순환하려면 `Ctrl+R`을 다시 누릅니다
4. **검색 범위**: 인라인 검색은 항상 모든 프로젝트의 프롬프트를 검색합니다
5. **일치 항목 수락**:
   * 현재 일치 항목을 수락하고 편집을 계속하려면 `Tab` 또는 `Esc`를 누릅니다
   * 수락하고 명령을 즉시 실행하려면 `Enter`를 누릅니다
6. **검색 취소**:
   * 취소하고 원래 입력을 복원하려면 `Ctrl+C`를 누릅니다
   * 취소하려면 빈 검색에서 `Backspace`를 누릅니다

인라인 검색은 최신 항목부터 전체 프롬프트 내역을 스캔하며 중복 항목은 최신 항목으로 축소됩니다. 전체 화면 대화 상자는 선택한 범위에서 가장 최근의 고유 프롬프트 100개를 나열합니다. 일치하는 프롬프트는 검색어가 강조 표시되어 표시되므로 이전 입력을 쉽게 찾아 재사용할 수 있습니다.

일치 항목을 수락하거나 검색을 취소하는 것은 Claude Code가 내역을 로드하는 중에도 즉시 적용됩니다. v2.1.202 이전에는 로드 중에 수락하거나 취소하면 내부 오류가 보고될 수 있었습니다.

## 백그라운드 Bash 명령

Claude Code는 백그라운드에서 Bash 명령을 실행할 수 있어 장시간 실행되는 프로세스가 실행되는 동안에도 작업을 계속할 수 있습니다.

### 백그라운드 작동 방식

Claude Code가 백그라운드에서 명령을 실행하면 명령을 비동기식으로 실행하고 즉시 백그라운드 작업 ID를 반환합니다. 명령이 백그라운드에서 계속 실행되는 동안 Claude Code는 새 프롬프트에 응답할 수 있습니다.

백그라운드에서 명령을 실행하려면 다음 중 하나를 수행할 수 있습니다:

* 백그라운드에서 명령을 실행하도록 Claude Code에 프롬프트
* 일반 Bash 도구 호출을 백그라운드로 이동하려면 `Ctrl+B`를 누릅니다. Tmux 사용자는 tmux의 접두사 키로 인해 `Ctrl+B`를 두 번 눌러야 합니다.

**핵심 기능:**

* 출력은 파일에 작성되며 Claude는 Read 도구를 사용하여 이를 검색할 수 있습니다
* 백그라운드 작업에는 추적 및 출력 검색을 위한 고유 ID가 있습니다
* Claude Code가 종료되면 백그라운드 작업이 자동으로 정리됩니다. 세션을 종료하는 대신 백그라운드로 전환하면 백그라운드 세션에 전달되어 계속 실행됩니다. [실행 중인 세션 백그라운드 전환](/docs/en/agent-view#from-inside-a-session)을 참조하세요.
* 출력이 5GB를 초과하면 백그라운드 작업이 자동으로 종료되며 stderr에 원인을 설명하는 노트가 포함됩니다
* macOS 및 Linux에서 세션이 30분 이상 유휴 상태이고 턴이나 서브에이전트가 실행되지 않는 경우, 운영 체제가 메모리 압박을 신호할 때 Claude Code가 실행 중인 백그라운드 작업을 종료합니다. 이를 끄려면 [`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`](/docs/en/env-vars)를 `1`로 설정하세요. Claude Code v2.1.193 이상 필요. [서브에이전트](/docs/en/sub-agents)가 소유한 백그라운드 명령은 60분 후에 종료되며 [`CLAUDE_SUBAGENT_BG_SHELL_MAX_MS`](/docs/en/env-vars)를 통해 밀리초 단위로 구성할 수 있습니다. v2.1.218 이전에는 두 제한 모두 `Ctrl+B`로 백그라운드로 이동한 명령을 보장하지 못했습니다

모든 백그라운드 작업 기능을 비활성화하려면 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` 환경 변수를 `1`로 설정하세요. 자세한 내용은 [환경 변수](/docs/en/env-vars)를 참조하세요.

**일반적인 백그라운드 전환 명령:**

* 빌드 도구 (webpack, vite, make)
* 패키지 관리자 (npm, yarn, pnpm)
* 테스트 러너 (jest, pytest)
* 개발 서버
* 장시간 실행되는 프로세스 (docker, terraform)

### `!` 접두사를 통한 셸 모드

입력 앞에 `!`를 붙여 Claude를 거치지 않고 직접 셸 명령을 실행하세요:

```bash theme={null}
! npm test
! git status
! ls -la
```

셸 모드:

* 대화 컨텍스트에 명령 및 해당 출력을 추가합니다
* 실시간 진행 상황 및 출력을 보여줍니다
* 장시간 실행되는 명령에 대해 동일한 `Ctrl+B` 백그라운드 전환을 지원합니다
* Claude가 명령을 해석하거나 승인할 필요가 없습니다
* 내역 기반 자동 완성을 지원합니다: 부분 명령을 입력하고 `Tab`을 눌러 현재 프로젝트의 이전 `!` 명령에서 완성합니다
* 모든 플랫폼에서 v2.1.193부터 라이브 파일 경로 자동 완성을 지원합니다: `./src/` 또는 `~/`와 같이 슬래시가 포함된 토큰을 입력하면 일치하는 파일 및 디렉토리 드롭다운이 표시되고 `Tab`을 눌러 수락합니다. Windows에서도 슬래시를 사용하세요; 드롭다운은 `\`가 아닌 `/`에 의해 트리거됩니다
* 빈 프롬프트에서 `Escape`, `Backspace` 또는 `Ctrl+U`로 종료합니다
* `!`로 시작하는 텍스트를 빈 프롬프트에 붙여넣으면 직접 입력한 `!` 동작과 동일하게 자동으로 셸 모드에 진입합니다

v2.1.186부터 명령 출력이 트랜스크립트에 들어오면 Claude가 이에 자동으로 응답하므로, `! npm test`를 실행하면 두 번째 프롬프트 없이 실패에 대한 설명을 얻을 수 있습니다. 응답 비용은 일반 프롬프트를 보내는 것과 동일합니다. 응답 없이 출력이 컨텍스트에 추가되던 이전 동작으로 복원하려면 `settings.json`에서 [`respondToBashCommands`](/docs/en/settings#available-settings)를 `false`로 설정하세요. v2.1.186 이전에는 셸 모드가 항상 응답 없이 출력을 컨텍스트에 추가했습니다.

이는 대화 컨텍스트를 유지하면서 빠른 셸 작업을 수행하는 데 유용합니다.

## 프롬프트 제안 (Prompt suggestions)

세션을 처음 열 때 시작하는 데 도움이 되도록 은색의 예시 명령이 프롬프트 입력에 나타납니다. Claude Code는 프로젝트의 git 내역에서 이를 선택하므로 최근에 작업한 파일이 반영됩니다.

Claude가 응답한 후에도 다중 파트 요청의 후속 단계나 워크플로의 자연스러운 연장선과 같이 대화 내역을 기반으로 제안이 계속 나타납니다.

* 제안을 프롬프트 입력에 배치하려면 `Tab` 또는 `Right 방향키`를 누르고 제출하려면 `Enter`를 누릅니다
* 취소하려면 입력을 시작하세요

제안은 부모 대화의 프롬프트 캐시를 재사용하는 백그라운드 요청으로 실행되므로 추가 비용이 최소화됩니다. Claude Code는 불필요한 비용을 피하기 위해 캐시가 비어 있을 때는 제안 생성을 건너뜁니다.

제안은 대화의 첫 턴 이후 및 플랜 모드에서는 자동으로 건너뜁니다.

print 모드에서는 기본적으로 꺼져 있습니다. 매 턴마다 `prompt_suggestion` 메시지를 내보내려면 `-p "<prompt>" --output-format stream-json --verbose`와 함께 [`--prompt-suggestions`](/docs/en/cli-reference#cli-flags)를 전달하세요.

프롬프트 제안을 완전히 비활성화하려면 환경 변수를 설정하거나 `/config`에서 설정을 토글하세요:

```bash theme={null}
export CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false
```

## 이모지 숏코드

프롬프트 입력에 `:` 뒤에 이모지 숏코드를 입력하여 이모지를 삽입하세요. Claude Code v2.1.217 이상 필요.

* `:heart:`와 같은 전체 숏코드를 입력하면 닫는 `:`를 입력하는 즉시 Claude Code가 이를 ❤️로 교체합니다
* 제안 팝업을 열려면 `:` 뒤에 이름의 두 자 이상(예: `:hea`)을 입력한 다음 `Tab` 또는 `Enter`를 눌러 강조 표시된 이모지를 삽입하세요

숏코드는 입력의 시작 부분에 오거나 공백 뒤에 와야 하므로 단어나 URL 내부의 `:`는 제안을 열지 않습니다.

이 기능을 끄려면 `settings.json`에서 [`emojiCompletionEnabled`](/docs/en/settings#available-settings)를 `false`로 설정하세요. 이는 제안 팝업과 인라인 교체를 모두 비활성화합니다.

## /btw를 이용한 사이드 질문

대화 내역에 추가하지 않고 현재 작업에 대해 빠른 질문을 하려면 `/btw`를 사용하세요. 빠른 답변을 원하지만 메인 컨텍스트를 어지럽히거나 장시간 실행 중인 작업에서 Claude를 이탈시키고 싶지 않을 때 유용합니다.

```
/btw what was the name of that config file again?
```

사이드 질문은 현재 대화에 대한 완전한 가시성을 가지므로 Claude가 이미 읽은 코드, 이전에 내린 결정 또는 세션의 다른 모든 것에 대해 질문할 수 있습니다. 질문과 답변은 영구적이지 않습니다: 닫을 수 있는 오버레이에 나타나며 대화 내역에 들어가지 않습니다.

* **Claude가 작업 중일 때도 가능**: Claude가 응답을 처리하는 동안에도 `/btw`를 실행할 수 있습니다. 사이드 질문은 독립적으로 실행되며 메인 턴을 중단하지 않습니다.
* **도구 접근 불가**: 사이드 질문은 이미 컨텍스트에 있는 내용으로만 답변합니다. Claude는 사이드 질문에 답변할 때 파일을 읽거나 명령을 실행하거나 검색할 수 없습니다.
* **단일 응답**: 오버레이에는 후속 턴이 없습니다. 스레드를 계속하려면 `f`를 사용하여 자체 세션으로 포크하세요.
* **저렴한 비용**: 사이드 질문은 부모 대화의 프롬프트 캐시를 재사용하므로 추가 비용이 최소화됩니다.

동일한 세션의 이전 사이드 질문은 현재 답변 위에 어둡게 처리된 목록으로 나타납니다. 대화 내역에는 포함되지 않지만 지울 때까지 오버레이에 표시된 상태로 유지됩니다.

오버레이를 닫은 후 다시 돌아가려면 질문 없이 `/btw`를 실행하세요. 오버레이가 가장 최근 교환에서 다시 열립니다. 이전 답변으로 다시 이동하려면 `Left`를 누르세요. v2.1.212 이전에는 질문 없는 `/btw`가 사용법 메시지를 출력했습니다.

답변이 나타나면 오버레이는 다음 키를 수락합니다.

| 키                        | 작업                                                                                                                                                                                                                                                                    |
| :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Space`, `Enter`, `Escape` | 답변을 닫고 프롬프트로 돌아가기                                                                                                                                                                                                                                                              |
| `Up` / `Down`              | 답변 스크롤                                                                                                                                                                                                                                                         |
| `Left` / `Right`           | 이 답변과 세션의 이전 `/btw` 답변 간 이동. `Left`는 이전 답변으로 이동하고 `Right`는 현재 답변으로 돌아옵니다. Claude Code v2.1.187 이상 필요                                                                                                         |
| `c`                        | 답변을 원시 마크다운으로 클립보드에 복사. 소스 텍스트가 아닌 하드 래핑된 터미널 렌더링을 캡처하는 마우스 선택 대신 사용하세요                                                                                                                                   |
| `f`                        | 새 세션으로 포크. 포크는 부모 대화와 이 질문 및 답변을 실제 트랜스크립트 턴으로 상속하므로 완전한 도구 접근 권한으로 계속할 수 있습니다. 원본 세션은 [`/resume`](/docs/en/commands) 아래에 보존됩니다. 로컬 세션에서만 가능합니다 |
| `x`                        | 현재 답변 위에 표시된 이전 `/btw` 교환 목록 지우기                                                                                                                                                                                                 |

`/btw`는 [서브에이전트](/docs/en/sub-agents)의 반대 개념입니다: 전체 대화를 볼 수 있지만 도구가 없는 반면, 서브에이전트는 완전한 도구를 가지지만 빈 컨텍스트로 시작합니다. Claude가 이 세션에서 이미 알고 있는 내용에 대해 질문하려면 `/btw`를 사용하고; 가서 새로운 것을 알아오려면 서브에이전트를 사용하세요.

## 작업 목록 (Task list)

작업 목록은 Claude의 할 일 체크리스트입니다: 다중 단계 작업을 계획하기 위해 Claude가 생성한 항목으로, 보류 중, 진행 중, 완료됨을 나타내는 표시기가 함께 나타납니다. 백그라운드 작업 보기와는 별개입니다. 실행 중인 셸 및 서브에이전트를 보려면 대신 [`/tasks`](/docs/en/commands)를 사용하세요.

* 작업 목록 보기를 토글하려면 `Ctrl+T`를 누릅니다. 디스플레이에는 한 번에 최대 5개의 작업이 표시됩니다. Claude가 아직 체크리스트 항목을 생성하지 않은 경우 표시할 항목이 없으므로 토글이 눈에 띄는 효과가 없습니다
* 모든 작업을 보거나 지우려면 Claude에게 직접 요청하세요: "show me all tasks" 또는 "clear all tasks"
* 작업은 컨텍스트 압축 간에도 유지되어 Claude가 대규모 프로젝트에서 조직적인 상태를 유지하도록 돕습니다
* 세션 간에 작업 목록을 공유하려면 `CLAUDE_CODE_TASK_LIST_ID`를 설정하여 `~/.claude/tasks/` 아래의 이름이 지정된 디렉토리를 사용하세요: `CLAUDE_CODE_TASK_LIST_ID=my-project claude`

## 세션 요약 (Session recap)

잠시 자리를 비웠다가 터미널로 돌아오면 Claude Code는 지금까지 세션에서 일어난 일에 대한 한 줄 요약을 보여줍니다. 요약은 마지막으로 완료된 턴 이후 3분 이상 지나고 터미널에 포커스가 맞춰지지 않았을 때 백그라운드에서 한 번 생성되므로, 다시 돌아왔을 때 준비되어 있습니다. 요약은 세션에 3턴 이상이 있을 때만 한 번 나타나며 연속으로 두 번 나타나지 않습니다.

요청 시 요약을 생성하려면 `/recap`을 실행하세요. 자동 요약을 끄려면 `/config`를 열고 **Session recap**을 비활성화하세요.

세션 요약은 모든 플랜과 제공자에 대해 기본적으로 켜져 있습니다. 비대화형 모드에서는 항상 요약을 건너끕니다.

## PR 리뷰 상태

열려 있는 풀 리퀘스트가 있는 브랜치에서 작업할 때 Claude Code는 바닥글에 "PR #446"과 같은 클릭 가능한 PR 링크를 표시합니다. 링크에는 리뷰 상태를 나타내는 색상 밑줄이 있습니다:

* 초록색: 승인됨 (approved)
* 노란색: 리뷰 대기 중 (pending review)
* 빨간색: 변경 요청됨 (changes requested)
* 회색: 초안 (draft)

풀 리퀘스트가 머지되거나 닫히면 배지가 사라집니다. 브라우저에서 풀 리퀘스트를 열려면 링크를 `Cmd+클릭` (macOS) 또는 `Ctrl+클릭` (Windows/Linux) 하세요. 상태는 60초마다 새로 고쳐지며 세션에서 `gh pr` 또는 `git push` 명령이 실행된 직후 새로 고쳐집니다.

Claude Code는 터미널에서 하이퍼링크 지원을 감지할 수 없는 경우에도 하이퍼링크로 배지를 렌더링합니다(SSH 또는 tmux를 통해 흔히 발생함). 배지를 일반 텍스트로 렌더링하려면 [`FORCE_HYPERLINK=0`](/docs/en/env-vars)을 설정하세요. v2.1.217 이전에는 감시에 성공한 경우에만 배지가 하이퍼링크였습니다.

<Note>
  PR 상태를 확인하려면 `gh` CLI가 설치되어 있고 인증되어 있어야 합니다 (`gh auth login`).
</Note>

# Claude Code Desktop에서 정기적인 예약 작업 설정하기

> Claude Code Desktop에서 예약된 작업을 설정하여 일일 코드 검토, 종속성 감사 또는 아침 브리핑을 위해 정기적으로 Claude를 자동 실행하세요.

예약된 작업(scheduled tasks)은 사용자가 선택한 시간과 빈도로 새 세션을 자동으로 시작합니다. 일일 코드 검토, 종속성 업데이트 검사, 또는 달력과 수신함에서 정보를 가져오는 아침 브리핑과 같은 정기적인 작업에 이를 사용하세요.

데스크톱 앱의 **Routines** 페이지에서는 로컬 예약 작업과 원격 [루틴](/docs/en/routines)을 모두 생성할 수 있습니다. 로컬 작업은 사용자의 파일 및 도구에 직접 접근하여 머신에서 실행되지만 앱이 열려 있고 컴퓨터가 켜져 있을 때만 실행됩니다. 원격 루틴은 컴퓨터가 꺼져 있을 때도 Anthropic 관리형 클라우드 인프라에서 실행되며, API 호출이나 GitHub 이벤트 시 실행할 수도 있습니다. 이 페이지에서는 로컬 예약 작업을 다룹니다; 원격 루틴 및 해당 트리거 옵션은 [루틴](/docs/en/routines)을 참조하세요.

## 예약 옵션 비교

Claude Code는 정기적인 작업이나 일회성 작업을 예약하는 세 가지 방법을 제공합니다:

| | [Cloud](/docs/en/routines) | [Desktop](/docs/en/desktop-scheduled-tasks) | [`/loop`](/docs/en/scheduled-tasks) |
| :------------------------- | :----------------------------- | :------------------------------------- | :---------------------------------- |
| 실행 위치 | Anthropic 클라우드 | 사용자의 머신 | 사용자의 머신 |
| 머신 켜짐 필요 | 아니오 | 예 | 예 |
| 열린 세션 필요 | 아니오 | 아니오 | 예 |
| 재시작 시 유지 | 예 | 예 | 만료되지 않은 경우 `--resume` 시 복원 |
| 로컬 파일 접근 | 아니오 (새로 복제) | 예 | 예 |
| MCP 서버 | 작업별로 구성된 커넥터 | [구성 파일](/docs/en/mcp) 및 커넥터 | 세션에서 상속 |
| 권한 프롬프트 | 아니오 (자율 실행) | 작업별 구성 가능 | 세션에서 상속 |
| 맞춤형 일정 | CLI의 `/schedule`을 통해 가능 | 예 | 예 |
| 최소 간격 | 1시간 | 1분 | 1분 |

<Tip>
  사용자의 머신 없이도 안정적으로 실행되어야 하는 작업에는 **클라우드 작업(cloud tasks)**을 사용하세요. 로컬 파일 및 도구에 대한 접근이 필요할 때는 **Desktop 작업(Desktop tasks)**을 사용하세요. 세션 중 빠른 폴링에는 **`/loop`**를 사용하세요.
</Tip>

<Note>
  기본적으로 예약된 작업은 미커밋 변경 사항을 포함하여 작업 디렉터리가 존재하는 상태에서 실행됩니다. 각 실행마다 [병렬 세션](/docs/en/desktop#work-in-parallel-with-sessions)이 작동하는 방식과 동일하게 격리된 Git 워크트리를 부여하려면 작업을 생성할 때 워크트리 토글을 활성화하세요.
</Note>

## 예약 작업 생성하기

사이드바에서 **Routines**를 클릭한 다음 **New routine**을 클릭하고 **Local**을 선택하세요. 다음 필드를 구성하세요:

| 필드 | 설명 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Name | 작업의 식별자입니다. 소문자 케밥 케이스(kebab-case)로 변환되어 디스크의 폴더 이름으로 사용됩니다. 작업 간에 고유해야 합니다. |
| Description | 작업 목록에 표시되는 짧은 요약입니다. |
| Instructions | 작업이 실행될 때 Claude가 수행해야 할 내용입니다. 프롬프트 상자에 메시지를 작성하는 방식과 동일하게 작성하세요. 지침 입력란에는 권한 모드 및 모델 선택기가 포함되어 있으며, 그 아래에서 작업 폴더와 격리된 워크트리에서 실행할지 여부를 선택합니다. |
| Schedule | 작업 실행 빈도입니다. 아래의 [일정 옵션](#schedule-options)을 참조하세요. |

작업을 저장하려면 폴더 지정이 필수적입니다. 해당 폴더를 아직 신뢰하지 않은 경우 Desktop에서 저장하기전에 신뢰할 것인지 묻습니다.

아무 세션에서나 원하는 내용을 설명하여 작업을 생성할 수도 있습니다. 예를 들어 "set up a daily code review that runs every morning at 9am"은 정기 작업을 생성하고, "remind me at 3pm tomorrow to check the deploy"는 실행 후 스스로 비활성화되는 일회성 작업을 생성합니다.

## 일정 옵션

Schedule 컨트롤에서 프리셋을 선택하세요:

* **Manual**: 일정 없이 **Run now**를 클릭할 때만 실행됩니다. 필요할 때 트리거하는 프롬프트를 저장하는 데 유용합니다.
* **Hourly**: 매시간 실행됩니다.
* **Daily**: 시간 선택기를 보여주며 기본값은 로컬 시간 오전 9:00입니다.
* **Weekdays**: Daily와 동일하지만 토요일과 일요일은 건너뜁니다.
* **Weekly**: 시간 선택기와 요일 선택기를 보여줍니다.

15분마다, 매월 1일 또는 특정 미래 시간의 단일 실행과 같이 선택기가 제공하지 않는 간격의 경우 아무 Desktop 세션에서나 Claude에게 일정을 설정하도록 요청하세요. 자연어를 사용하세요; 예를 들어 "schedule a task to run all the tests every 6 hours."

## 예약 작업 실행 방식

예약된 작업은 사용자의 머신에서 실행됩니다. Desktop은 앱이 열려 있는 동안 매분 일정을 확인하며 작업 기한이 되면 열려 있는 수동 세션과 무관하게 새 세션을 시작합니다. 각 작업은 API 트래픽을 분산시키기 위해 예정된 시간 이후 수분의 짧은 지연시간을 갖습니다. 지연시간은 결정적(deterministic)입니다: 동일한 작업은 항상 동일한 오프셋에서 시작됩니다.

작업이 실행되면 데스크톱 알림을 받게 되며 사이드바의 **Scheduled** 섹션 아래에 새 세션이 나타납니다. 해당 세션을 열어 Claude가 수행한 작업을 확인하고, 변경 사항을 검토하거나, 권한 프롬프트에 응답하세요. 세션은 다른 세션과 동일하게 작동합니다: Claude는 파일을 편집하고, 명령을 실행하고, 커밋을 생성하고, 풀 리퀘스트를 열 수 있습니다.

작업은 데스크톱 앱이 실행 중이고 컴퓨터가 켜져 있을 때만 실행됩니다. 컴퓨터가 예약된 시간에 절전 상태인 경우 실행이 건너뛰어집니다. 대기 절전을 방지하려면 Settings의 **Desktop app → General** 아래에서 **Keep computer awake**를 활성화하세요. 랩톱 덮개를 닫으면 여전히 절전 모드로 들어갑니다. 컴퓨터가 꺼져 있을 때도 실행해야 하거나 API 호출이나 GitHub 이벤트로 트리거되어야 하는 작업의 경우 원격 [루틴](/docs/en/routines)을 대신 생성하세요.

## 놓친 실행 (Missed runs)

앱이 시작되거나 컴퓨터가 켜질 때 Desktop은 지난 7일 동안 각 작업이 놓친 실행이 있는지 확인합니다. 놓친 것이 있다면 Desktop은 가장 최근에 놓친 시간에 대해 정확히 1회의 보충(catch-up) 실행을 시작하고 이전 실행은 파기합니다. 6일을 놓친 일일 작업은 컴퓨터가 켜질 때 한 번 실행됩니다. Desktop은 보충 실행이 시작될 때 알림을 표시합니다.

프롬프트를 작성할 때 이를 염두에 두세요. 오전 9시에 예약된 작업은 컴퓨터가 하루 종일 절전 상태였던 경우 오후 11시에 실행될 수 있습니다. 타이밍이 중요하다면 프롬프트 자체에 가드레일을 추가하세요. 예: "Only review today's commits. If it's after 5pm, skip the review and just post a summary of what was missed."

## 예약 작업에 대한 권한

각 작업에는 작업을 생성하거나 편집할 때 설정하는 자체 권한 모드가 있습니다. `~/.claude/settings.json`에 설정된 허용 규칙도 예약 작업 세션에 적용됩니다. 작업이 Ask 모드에서 실행되고 권한이 없는 도구를 실행해야 하는 경우 승인할 때까지 실행이 일시 중지됩니다. 나중에 응답할 수 있도록 세션은 사이드바에 열려 있는 상태로 유지됩니다.

일시 중지를 방지하려면 작업을 생성한 후 **Run now**를 클릭하고 권한 프롬프트를 관찰한 다음 각 프롬프트에 대해 "always allow"를 선택하세요. 해당 작업의 향후 실행은 프롬프트 없이 동일한 도구를 자동 승인합니다. 작업 상세 페이지에서 이러한 승인을 검토하고 취소할 수 있습니다.

[조직에서 `ask`로 설정한 커넥터 도구](/docs/en/mcp#organization-controls-on-connector-tools) 및 [`requiresUserInteraction`으로 표시된 MCP 도구](/docs/en/mcp#require-approval-for-a-specific-tool)는 호출할 때마다 프롬프트를 표시하며 항상 허용 옵션을 제공하지 않습니다. 이러한 도구를 호출하는 실행은 매번 일시 중지됩니다.

## 예약 작업 관리하기

**Routines** 목록에서 작업을 클릭하여 상세 페이지를 여세요. 여기에서 다음을 수행할 수 있습니다:

* **Run now**: 다음 예정 시간까지 기다리지 않고 작업을 즉시 시작
* **Status**: 작업을 삭제하지 않고 예약된 실행을 일시 중지하거나 재개하기 위해 Active 및 Paused 간 전환
* **Edit**: 지침, 일정, 폴더 또는 기타 설정 변경
* **Review history**: 건너뛴 실행을 포함하여 과거의 모든 실행을 검토합니다. 건너뛴 항목에 마우스를 올리면 이유가 표시됩니다: 컴퓨터가 절전 상태였음, 이전 실행이 아직 진행 중이었음, 또는 다른 예약 작업이 이미 실행 중이었음. 더 오래된 항목을 로드하려면 **Show more**를 클릭하세요.
* **Review allowed permissions**: **Always allowed** 패널에서 이 작업에 대해 저장된 도구 승인 내용을 확인하고 취소
* **Delete**: 작업을 제거하고 작업이 생성한 모든 세션을 아카이브합니다. 확인 대화 상자에 **Also delete files on disk** 체크박스가 나타납니다; `~/.claude/scheduled-tasks/`에서 작업의 `SKILL.md` 파일 및 관련 데이터도 제거하려면 이를 체크하세요.

아무 Desktop 세션에서나 Claude에게 요청하여 작업을 나열, 생성, 편집 및 일시 중지할 수도 있습니다. 예를 들어 "pause my dependency-audit task" 또는 "show me my scheduled tasks." 작업을 삭제하려면 상세 페이지의 **Delete** 버튼을 사용하세요.

예약된 작업은 `update_scheduled_task` MCP 도구를 사용하여 실행 중인 세션 내에서 자체 일정이나 프롬프트를 수정할 수도 있습니다. 이를 통해 발견된 내용을 바탕으로 작업이 스스로 일정을 변경할 수 있습니다. 예를 들어 릴리스 브랜치가 생성된 것을 감지했을 때 코드 검토가 더 일찍 실행되도록 일정을 변경하는 식입니다.

디스크에서 작업의 프롬프트를 편집하려면 `~/.claude/scheduled-tasks/<task-name>/SKILL.md`(또는 설정된 경우 [`CLAUDE_CONFIG_DIR`](/docs/en/env-vars) 아래)를 여세요. 이 파일은 `name` 및 `description`에 YAML 프론트매터를 사용하며 프롬프트가 본문이 됩니다. 변경 사항은 다음 실행 시 적용됩니다. 일정, 폴더, 모델 및 활성화 상태는 이 파일에 없으므로 Edit 양식을 통해 변경하거나 Claude에게 요청하세요.

# 커뮤니케이션 킷 (Communications kit)

> 엔지니어링 조직에 Claude Code를 배포하기 위한 출시 공지, 드립 캠페인 메시지 및 FAQ 응답 템플릿입니다.

이 페이지는 엔지니어링 팀에 Claude Code를 배포하는 관리자 및 엔지니어링 리드를 위한 것입니다. 바로 사용할 수 있는 출시 공지 텍스트, 팁과 노하우 드립 캠페인, 자주 묻는 질문에 대한 한 줄 FAQ 응답을 제공합니다.

<Note>
  여기에 있는 모든 내용은 완성된 초안이 아니라 작성용 초안(draft copy)으로 취급하세요. 각 메시지를 조직의 톤앤매너에 맞게 재작성하고, 예시 작업은 자체 코드베이스의 실제 버그 및 모듈로 교체하며, 발송 전에 `[대괄호 표시된 자리를]` 교체하세요. 도입을 촉진하는 공지문은 회사의 동료가 작성한 것처럼 읽히는 문구입니다.
</Note>

## 출시 공지문

두 가지 형식의 기본 공지문 1개와 두 가지 선택적 변형 공지문입니다. 배포 상황에 맞는 것을 선택하고 필요한 내용을 수정하여 사용하세요.

### 발송 전 체크리스트

공지문이 나갈 전에 이 체크리스트를 확인하세요. 각 항목은 출시 당일 지원 스레드로 변질될 수 있는 공백을 메워줍니다.

| 항목 | 중요한 이유 |
| :--- | :--- |
| `#claude-code` 채널이 생성되고 메시지에 링크됨 | 질문이 수집될 한 공간을 제공함 |
| 사용자 환경의 하나 이상의 머신에서 설치 명령 테스트 완료 | 모든 사람이 한 번에 몰리기 전에 프록시나 방화벽 문제를 포착함 |
| 보안 및 데이터 처리 링크 준비 완료 ([데이터 사용량](/docs/en/data-usage) 또는 내부 동등 문서) | "내 코드는 어디로 가나요?"라는 질문이 첫 번째 답변이 될 것임 |
| 코드베이스의 실제 버그나 파일 중 콘크리트한 첫 번째 작업 선택 | 일반적인 예시는 전환되지 않음; "`auth_test.go`의 간헐적 테스트 수정"은 효과가 있음 |
| 첫 48시간 동안 채널을 담당할 지정된 관리자 배치 | 답변되지 않은 출시 당일 질문은 추진력을 꺾음 |
| 공지문을 발송하거나 공동 서명할 경영진(C-suite) 스폰서 참여 | 경영진 명의로 발송된 출시 공지는 관리자 발송 공지보다 첫 주 도입률이 일관되게 높음 |

### 경영진 스폰서 변형 공지문

스폰서 경영진(CTO, CIO 또는 엔지니어링 부사장 등)의 이름과 계정으로 이 공지문을 발송하세요. 경영진 명의로 나가는 공지는 관리자나 툴링 팀이 발송하는 동일한 메시지보다 개봉률과 첫 주 활성화율이 일관되게 더 높습니다. 이는 선택적 실험이 아닌 회사 차원의 우선순위임을 나타냅니다.

이 버전은 시도(설치 후 1개의 실제 작업 실행)라는 하나의 요청에 집중하도록 의도적으로 간소화되었습니다. 경영진의 역할은 메시지가 확실히 전달되도록 하는 것이며, 기본 공지문과 `#claude-code` 채널이 구체적인 방법을 처리합니다.

## 팁과 노하우 드립 캠페인

출시 후 기능 활성화를 유도하기 위해 설계된 바로 복사하여 사용할 수 있는 Slack 또는 Teams 메시지입니다. 각각 동일한 패턴을 따릅니다: 훅(hook), 유용한 결과, "지금 시도해 보기" 프롬프트, 문서 링크. `#claude-code` 채널에 일주일에 한 두 번씩 발송하거나 팀의 부족한 부분에 맞는 메시지를 선택하세요. 순서 없이 독립적으로 사용할 수 있습니다.

각 블록의 메시지 본문을 Slack이나 Teams에 직접 복사하세요. 발송 전에 `[대괄호 표시된 자리]`를 교체하세요.

### 시작하기

**상황에 맞는 모델 선택**

```markdown theme={null}
🎯 *팁: 상황에 맞는 모델 매칭하기*

오타 하나 수정하는 데 Opus를 사용하는 것은 컴퓨팅 자원 낭비입니다. 12개 파일의
리팩토링에 Haiku를 사용하는 것은 재작업을 부르는 길입니다.

Claude Code는 Claude 앱과 동일한 모델을 사용하며 세션 중간에 전환할 수 있습니다.
*Sonnet*은 일상적인 기능 작업, 버그 수정, 테스트, 리뷰를 위한 기본 모델입니다.
대규모 리팩토링, 까다로운 디버깅 또는 중요한 변경 사항에는 *Opus*를 사용하세요.
속도가 중요한 빠른 질문, 포맷팅, 기계적인 편집에는 *Haiku*로 낮추세요.
*Fable 5*는 가장 어렵고 오래 걸리는 작업에 가장 강력한 모델입니다. 기본값은
아니므로 `/model fable`로 선택하세요. 사이버 보안 및 생물학 관련 콘텐츠는
자동으로 Opus로 대체(fallback)됩니다.

*지금 시도해 보기:* 아직 하지 않았다면 `/model`을 입력하고 Sonnet을 선택하세요.
대부분의 작업에 가장 적합한 기본값입니다.

📖 모델 구성 → https://code.claude.com/docs/en/model-config
```

| 모델 | 용도 |
| :--- | :--- |
| Fable 5 | 가장 어렵고 오래 걸리는 작업. 수동 선택 전용: `/model fable`로 선택. 사이버 보안 또는 생물학 콘텐츠는 [자동으로 Opus로 대체됨](/docs/en/model-config#automatic-model-fallback). |
| Opus | 대규모 리팩토링, 복잡한 디버깅, 아키텍처 결정, 중요한 변경 사항 |
| Sonnet | 일상적인 기능 작업, 버그 수정, 테스트, 문서화, 코드 리뷰. 권장 기본값. |
| Haiku | 빠른 질문, 포맷팅, 기계적인 편집, 빠른 반복 작업 |

**첫 10분 동안 시도해 볼 빠른 성공 사례**

```markdown theme={null}
🚀 *팁: 첫 10분 동안 시도해 볼 3가지*

Claude Code를 설치했지만 실제로 무엇을 물어봐야 할지 모르겠나요? 일주일 내내
괴롭혔던 작업부터 시작해 보세요.

  - 짜증 나는 문제 수정: "[파일]의 테스트가 간헐적으로 실패하는데 원인을 찾아줘"
  - 작성하지 않은 코드 파악: "[모듈]이 어떻게 작동하는지 설명해 줘"
  - 푸시 전 자체 검증: "작업 중인 diff를 보고 위험해 보이는 부분을 알려줘"

이 중 어느 것도 별도 설정이 필요하지 않습니다. 리포지토리로 `cd` 이동하여 `claude`를 실행하세요.

*지금 시도해 보기:* 미루고 있던 버그를 선택하고 오류 메시지를 붙여넣어 보세요.
```

### 제어 및 안전성

**권한 모드 (Permission modes)**

```markdown theme={null}
🛡️ *팁: "보기만 하고 건드리지 않기"와 "알아서 처리하기" 사이의 단 하나의 키*

때로는 Claude가 모든 편집 전 물어보기를 바라고, 때로는 그냥 빠르게 처리되기를 바랍니다.
하나의 모드만 영원히 선택할 필요는 없습니다.

*Shift+Tab*을 누르면 Claude가 확인 없이 수행할 수 있는 권한 수준이 순환됩니다:
*Manual*(`default` 설정 값)은 파일 편집 및 대부분의 셸 명령 전에 묻고,
*acceptEdits*는 파일 편집과 공통 파일시스템 명령을 통과시키면서 다른 셸 명령 전에는 확인을 거치며,
*plan*은 아무것도 건드리지 않고 승인을 위한 계획을 제안합니다. 플랜 모드는
신뢰를 쌓는 모드이므로 여러 파일에 영향을 주는 작업은 여기서 시작하세요.

*지금 시도해 보기:* 다음 리팩토링 시 "plan"이 보일 때까지 Shift+Tab을 누른 다음
변경 사항을 설명해 보세요. 단 하나의 파일도 이동하기 전에 완전한 제안을 받게 됩니다.
```

### 프롬프트 템플릿

설치했지만 무엇을 물어봐야 할지 모르는 엔지니어들에게 이 스타터 프롬프트를 공유하세요. 각 프롬프트는 실제 세션에 입력할 구문 형태로 작성되었습니다; 대괄호 부분을 자체 리포지토리의 파일로 교체하세요.

| 작업 | 프롬프트 |
| :--- | :--- |
| 버그 수정 | "the tests in \[file] are failing, figure out why and fix it" |
| 코드 이해 | "walk me through how \[module] works, then tell me where the entry point is" |
| 안전한 리팩토링 | "refactor \[module] to \[goal], use plan mode so I can review first" |
| 테스트 작성 | "write tests for \[file] that cover the edge cases around \[scenario]" |
| 커밋 전 검토 | "look at my working diff and tell me what looks risky" |
| PR 생성 | "fix \[issue], write a conventional commit, and open a PR with a summary" |
| 스킬 생성 | "make me a /ship skill that runs tests and lint before commit" |
| 스택 트레이스 디버깅 | "here's the stack trace, find the root cause, don't just paper over it" |

<Tip>
  Claude Code는 자주 업데이트됩니다. 사내에 배포하기 전에 [문서 홈 페이지](/docs/en/overview)에서 버전별 세부 정보를 확인하세요.
</Tip>

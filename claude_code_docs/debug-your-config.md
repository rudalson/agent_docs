# 구성 디버깅하기

> CLAUDE.md, 설정, 훅, MCP 서버 또는 스킬이 적용되지 않는 이유를 진단하세요. 실제로 로드된 항목을 확인하려면 /context, /doctor, /hooks 및 /mcp를 사용하세요.

Claude가 지침을 무시하거나 구성한 기능이 표시되지 않는 경우, 주요 원인은 파일이 로드되지 않았거나 예상과 다른 위치에서 로드되었거나 다른 파일이 재정의(override)했기 때문입니다. 이 가이드에서는 Claude Code가 실제 어떤 내용을 로드했는지 검사하여 어떤 원인이 해당되는지 좁히는 방법을 보여줍니다.

설치, 인증 및 연결 문제는 [설치 및 로그인 문제 해결](/docs/en/troubleshoot-install)을 참조하세요.

## 컨텍스트에 로드된 항목 확인

`/context` 명령은 현재 세션의 컨텍스트 창을 차지하고 있는 모든 항목을 시스템 프롬프트, 시스템 도구, MCP 도구, 로드된 소스별 사용자 지정 서브에이전트, 메모리 파일, 스킬 및 대화 메시지 등 카테고리별로 나누어 보여줍니다. 먼저 이 명령을 실행하여 `CLAUDE.md`, 규칙 또는 스킬 설명이 존재하는지 확인하세요.

특정 카테고리에 대한 자세한 내용은 다음 전용 명령을 사용하세요:

| 명령 | 표시 내용 |
| :--------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/memory` | 각 파일을 편집기에서 열 수 있는 옵션과 함께 사용자 및 프로젝트 범위의 메모리 파일 위치, 자동 메모리 폴더 접근 및 자동 메모리 토글 |
| `/skills` | 프로젝트, 사용자 및 플러그인 소스에서 사용 가능한 스킬 |
| `/hooks` | 활성 훅 구성 |
| `/mcp` | 연결된 MCP 서버 및 해당 상태 |
| `/permissions` | 현재 적용 중인 해결된 허용 및 거부 규칙 |
| `/doctor` | 설정 점검: 설치 상태, 잘못된 설정 파일, 사용되지 않는 확장 기능, 동일한 디렉터리의 중복된 [서브에이전트](/docs/en/sub-agents) 이름, 그리고 체크인된 `CLAUDE.md` 콘텐츠 중 Claude가 코드베이스로부터 도출할 수 있는 항목과 제안된 수정 사항 |
| `/debug [issue]` | 세션에 대한 디버그 로깅을 활성화하고 로그 출력 및 설정 경로를 사용하여 Claude가 진단하도록 유도 |
| `/status` | 관리형 설정이 적용 중인지 여부를 포함하여 활성 설정 소스 |

메모리 파일이 `/context` 분석에서 누락된 경우 [CLAUDE.md 파일 로드 방식](/docs/en/memory#how-claude-md-files-load)에 따라 위치를 확인하세요. 하위 디렉터리의 `CLAUDE.md` 파일은 세션 시작 시가 아니라 Claude가 Read 도구로 해당 디렉터리의 파일을 읽을 때 필요에 따라 로드됩니다.

`/context`에서 파일이 로드되었음을 확인했지만 Claude가 여전히 특정 지침을 따르지 않는 경우, 문제 원인은 파일이 로드되었는지 여부가 아니라 지침이 작성된 방식일 가능성이 높습니다. CLAUDE.md는 프로젝트 컨벤션, 빌드 명령, 파일 위치와 같이 새 팀원에게 제공할 지침에 효과적입니다.

지침이 여러 가지로 해석될 만큼 모호하거나, 두 파일이 충돌하는 지시를 주거나, 파일이 너무 길어져 개별 규칙에 대한 주의가 줄어들면 지침 준수율이 떨어집니다. [효과적인 지침 작성법](/docs/en/memory#write-effective-instructions)에서는 준수율을 높게 유지하는 구체성, 크기 및 구조 패턴을 다룹니다.

<Note>
  CLAUDE.md와 권한은 서로 다른 문제를 해결합니다. CLAUDE.md는 프로젝트 작동 방식을 Claude에게 알려주어 올바른 결정을 내리도록 돕습니다. [권한](/docs/en/permissions) 및 [훅](/docs/en/hooks)은 Claude의 결정과 관계없이 제한을 강제합니다. "우리는 여기서 이런 방식으로 처리합니다"에는 CLAUDE.md를 사용하세요. 가이드 대신 보장이 필요한 보안 경계 및 절대로 일어나서는 안 되는 일에는 권한이나 훅을 사용하세요.
</Note>

## 해결된 설정 확인

설정은 관리형, 사용자, 프로젝트 및 로컬 범위에 걸쳐 병합됩니다. 관리형 설정이 존재할 경우 항상 최우선 적용됩니다. 나머지 중에서 더 좁은 범위가 local, project, user 순으로 더 넓은 범위를 재정의합니다. 일부 설정은 명령줄 플래그나 [환경 변수](/docs/en/env-vars)에 의해 설정될 수도 있으며, 이는 또 다른 재정의 레이어로 작동합니다. 설정이 적용되지 않는 것 같으면 설정한 값이 다른 범위나 환경 변수에 의해 재정의되었을 가능성이 큽니다.

`/doctor`를 실행하여 구성 및 설치 상태를 확인하세요. 잘못된 설정 파일, 중복 설치, 사용되지 않는 확장 기능, 그리고 {/* min-version: 2.1.206 */}Claude가 코드베이스에서 도출할 수 있는 체크인된 `CLAUDE.md` 콘텐츠를 포함하여 찾아낸 결과를 보고하고 사용자가 확인한 후에만 제안된 수정 사항을 적용합니다. `CLAUDE.md` 정리 점검에는 Claude Code v2.1.206 이상이 필요합니다. v2.1.205 이전에는 `/doctor`가 읽기 전용 진단 화면을 열었고 `f`를 누르면 진단 보고서가 Claude로 전송되어 수정되었습니다.

터미널에서 `claude doctor`를 실행하면 세션을 시작하지 않고 읽기 전용 설치 및 설정 진단 정보를 출력합니다.

`/status`를 실행하여 관리형 설정이 적용 중인지 여부를 포함하여 활성화된 설정 소스를 확인하세요. 특정 키에 대해 어떤 범위가 우선하는지 이해하려면 [범위 상호작용 방식](/docs/en/settings#how-scopes-interact)을 참조하세요.

## MCP 서버 확인

`/mcp`를 실행하여 모든 구성된 서버, 연결 상태 및 현재 프로젝트에 대해 승인했는지 여부를 확인하세요. 서버가 올바르게 정의되어 있어도 다음과 같은 일반적인 이유로 도구를 제공하지 못할 수 있습니다:

* `.mcp.json`에 구성된 프로젝트 범위 서버는 최초 1회 승인이 필요합니다. 프롬프트를 닫은 경우 `/mcp`에서 승인할 때까지 서버가 비활성화 상태로 유지됩니다.
* 시작에 실패한 서버는 `/mcp`에서 실패로 표시됩니다. `command`나 `args`에 사용된 상대 파일 경로는 `.mcp.json` 위치가 아니라 Claude Code를 실행한 디렉터리를 기준 경로로 확인하므로 자주 원인이 됩니다.
* 연결된 것으로 표시되지만 도구 수가 0개로 표시되는 서버는 성공적으로 시작되었지만 도구 목록을 반환하지 않는 상태입니다. `/mcp`에서 **Reconnect**를 선택하세요. 개수가 계속 0으로 유지되면 `claude --debug mcp`를 실행하여 서버의 stderr 출력을 확인하세요.

구성 위치 및 범위 규칙은 [MCP](/docs/en/mcp)를 참조하세요.

## 훅 확인

`/hooks`를 실행하여 현재 세션에 등록된 모든 훅을 이벤트별로 그룹화하여 확인하세요. 정의한 훅이 표시되지 않는 경우 해당 훅을 읽지 못하고 있는 것입니다: 훅은 단독 파일이 아니라 설정 파일의 `"hooks"` 키 아래에 들어가야 합니다.

훅이 표시되지만 실행되지 않는 경우 매처(matcher)가 원인인 경우가 많습니다. 다음 오류가 있는지 매처를 확인하세요:

* `matcher` 필드는 `"Edit|Write"`와 같이 여러 도구 이름과 일치시키기 위해 `|`를 사용하는 단일 문자열입니다. {/* min-version: 2.1.191 */}`,` 구분 기호도 동일하므로 `"Edit,Write"`는 동일한 도구와 일치합니다. v2.1.191 이전에는 쉼표가 정규식 계산으로 넘어가 매처가 일치하지 않았으므로, 아직 v2.1.191 버전이 아니라면 `|`를 사용하세요.
* 도구 이름에 오타가 있으면 매처가 아무것도 일치시키지 못해 훅이 알림 없이 실패합니다.
* 배열 값은 스키마 오류입니다: Claude Code는 설정 오류 알림을 표시하고 사용자, 프로젝트 또는 로컬 설정 파일 전체를 거부하며, `claude doctor`는 유효성 검사 실패를 보고하고 해당 파일의 어떤 훅도 `/hooks`에 표시되지 않습니다. [관리형 설정](/docs/en/settings#settings-files)에서는 잘못된 항목만 제거되고 파일의 다른 훅은 여전히 적용됩니다.

`settings.json` 편집 내용은 짧은 파일 안정화 지연 후 실행 중인 세션에 적용됩니다. 다시 시작할 필요가 없습니다. 저장 후 몇 초가 지나도 `/hooks`에 이전 정의가 계속 표시되면 `/hooks`를 다시 실행하여 뷰를 새로 고치세요.

`/hooks`에 훅이 표시되지만 여전히 실행되지 않으면 다음 단계는 훅 평가를 라이브로 모니터링하는 것입니다. `claude --debug hooks`로 세션을 시작하고 도구 호출을 트리거하세요. 디버그 로그에는 각 이벤트, 확인된 매처, 훅의 종료 코드 및 출력이 기록됩니다. 로그 형식은 [훅 디버깅](/docs/en/hooks#debug-hooks)을, 일반적인 실패 패턴은 [훅 문제 해결](/docs/en/hooks-guide#limitations-and-troubleshooting)을 참조하세요.

## 깨끗한 구성으로 테스트

{/* min-version: 2.1.169 */}`CLAUDE.md`, 스킬, 플러그인, 훅, MCP 서버, 커스텀 명령 및 에이전트를 포함한 모든 사용자 지정 기능이 비활성화된 세션을 시작하는 [`claude --safe-mode`](/docs/en/cli-reference#cli-flags)로 시작하세요. 인증, 모델 선택, 기본 제공 도구 및 권한은 정상적으로 작동합니다. 안전 모드에서 문제가 사라진 경우 이러한 커스텀 기능 중 하나가 원인입니다; 위의 표적 점검을 통해 원인을 찾으세요. 안전 모드에서도 조직의 관리형 훅 및 설정 정책은 적용됩니다. 관리형 플러그인, 스킬, CLAUDE.md 및 MCP 서버는 꺼집니다.

안전 모드에서도 문제가 지속되거나 설정 자체에 의심이 가는 경우 일반적인 설정에서 아무것도 로드하지 않는 세션과 비교해보세요. [`CLAUDE_CONFIG_DIR`](/docs/en/env-vars)을 빈 디렉터리로 지정하여 `~/.claude` 아래의 모든 항목을 건너뛰고, `.claude` 폴더, `.mcp.json` 또는 `CLAUDE.md`가 없는 디렉터리에서 실행하여 프로젝트 구성도 건너뜁니다.

```bash theme={null}
cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude
```

깨끗한 세션에는 사용자 또는 프로젝트 설정, 훅, MCP 서버, 플러그인 또는 메모리가 없습니다. 최초 실행 시 테마 선택으로 시작하는 첫 실행 설정 화면이 표시됩니다. 이 화면이 보이면 깨끗한 구성 디렉터리가 적용된 것입니다. 동일한 디렉터리로 나중에 실행하면 Claude Code가 거기에 온보딩 상태를 저장하므로 이 화면을 건너뜁니다.

* 조직에서 관리형 설정을 배포한 경우 `~/.claude` 외부의 시스템 경로에 존재하므로 여전히 적용됩니다.
* Linux 및 Windows에서는 자격 증명이 구성 디렉터리 아래에 저장되므로 다시 로그인하라는 메시지가 표시됩니다.
* macOS에서는 자격 증명이 Keychain에 있어 깨끗한 세션으로 인계됩니다.

여기서 문제가 사라진 경우 실제 `~/.claude` 또는 프로젝트 `.claude` 파일 어딘가에 원인이 있습니다. 임시 디렉터리에 파일을 복사하거나 프로젝트에서 시작하여 파일들을 하나씩 다시 도입하면서 어떤 파일이 원인인지 확인하세요. 깨끗한 세션에서도 문제가 지속된다면 원인은 사용자 및 프로젝트 구성 외부에 있습니다. `/status`를 실행하여 관리형 설정이 적용 중인지 확인하고, Claude Code에 영향을 미치는 [환경 변수](/docs/en/env-vars)를 찾아본 다음 [문제 해결](/docs/en/troubleshooting)을 참조하세요.

## 일반적인 원인 확인

가장 혼란스러운 구성 문제는 몇 가지 위치 및 구문 규칙으로 귀결됩니다. 버그라고 가정하기 전에 다음 사항을 확인하세요:

| 증상 | 원인 | 수정 방법 |
| :------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 훅이 실행되지 않음 | `matcher`가 문자열 대신 JSON 배열임 | `"Edit\|Write"`와 같이 여러 도구와 일치시키려면 `\|`가 포함된 단일 문자열을 사용하세요. [매처 패턴](/docs/en/hooks#matcher-patterns)을 참조하세요. |
| 훅이 실행되지 않음 | v2.1.191 이전 버전에서 `matcher`가 `,`를 구분 기호로 사용함 | {/* min-version: 2.1.191 */}Claude Code v2.1.191 이상에서는 `,`를 `\|`와 같은 목록 구분 기호로 취급합니다. 이전 버전에서는 쉼표를 일반 문자로 평가하므로 `"Edit,Write"`는 아무것도 일치하지 않습니다. `\|`를 대신 사용하거나 Claude Code를 업그레이드하세요. |
| 훅이 실행되지 않음 | `matcher` 값이 소문자임 (예: `"bash"`) | 일치 검사는 대소문자를 구분합니다. 도구 이름은 대문자로 시작합니다: `Bash`, `Edit`, `Write`, `Read`. |

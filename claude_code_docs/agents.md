# 에이전트 병렬 실행하기

> 서브에이전트, 에이전트 뷰, 에이전트 팀, 동적 워크플로 등 Claude Code가 여러 작업을 동시에 수행하는 방식을 비교합니다.

[서브에이전트](/docs/en/sub-agents), [에이전트 뷰](/docs/en/agent-view), [에이전트 팀](/docs/en/agent-teams), [동적 워크플로](/docs/en/workflows)는 각각 다른 방식으로 작업을 병렬 처리합니다. 대화에 직접 머무를 것인지, 작업을 위임하고 나중에 확인할 것인지, Claude가 여러 작업자를 조율하도록 할 것인지에 따라 적절한 방식을 선택하세요.

| 접근 방식 | 제공하는 기능 | 사용 시점 |
| :--------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [서브에이전트](/docs/en/sub-agents) | 단일 세션 내에서 자체 컨텍스트로 보조 작업을 수행하고 요약을 반환하는 위임된 작업자 | 보조 작업이 검색 결과, 로그, 파일 내용으로 메인 대화를 가득 채울 것 같을 때 |
| [에이전트 뷰](/docs/en/agent-view) | `claude agents`로 열며, 백그라운드에서 실행되는 세션을 전달하고 모니터링하는 단일 화면. 연구 프리뷰 | 여러 독립된 작업이 있어 전달하고, 한눈에 상태를 확인하며, 도움이 필요할 때만 개입하고 싶을 때 |
| [에이전트 팀](/docs/en/agent-teams) | 리더가 관리하며 공유 작업 목록과 에이전트 간 메시징을 갖춘 여러 조율된 세션. 실험적 기능이며 기본적으로 비활성화됨 | Claude가 프로젝트를 조각으로 나누고, 할당하며, 작업자 간의 동기화를 유지하도록 하고 싶을 때 |
| [동적 워크플로](/docs/en/workflows) | 한 번에 한 턴씩 조율하기에 너무 크거나 여러 번의 패스가 필요한 작업을 위해, 여러 서브에이전트를 실행하고 결과를 교차 검증하는 스크립트 | 작업 범위가 소수의 서브에이전트를 넘어서거나, 결과를 서로 검증하고 싶을 때: 코드베이스 전체 감사, 500개 파일 마이그레이션, 교차 검증 연구 등 |

모든 접근 방식에서 작업자는 Claude 세션입니다. 다른 도구를 포함하려면 [MCP 서버](/docs/en/mcp)로 Claude에 노출하세요.

에이전트를 직접 실행하는 방식은 아니지만 이 작업을 지원하는 두 가지 도구가 더 있습니다:

* [워크트리(Worktrees)](/docs/en/worktrees): 각 세션에 별도의 git 체크아웃을 제공하여 병렬 세션이 동일한 파일을 편집하지 않도록 합니다. 직접 실행하는 세션에 사용하세요. 에이전트 뷰는 전달된 각 세션을 자동으로 고유한 워크트리로 이동하며, 직접 생성한 서브에이전트도 워크트리를 받을 수 있습니다.
* [`/batch`](/docs/en/commands): Claude가 하나의 큰 변경 사항을 5~30개의 워크트리로 격리된 서브에이전트로 나누어 각각 풀 리퀘스트를 생성하도록 하는 [스킬](/docs/en/skills)입니다. 서브에이전트와 워크트리를 패키지화하여 사용하는 형태입니다.

몇 가지 다른 기능도 사용자가 매 단계를 지시하지 않고 Claude를 실행하지만, 작업 분할과는 다른 문제를 해결합니다:

* [백그라운드 bash 명령](/docs/en/interactive-mode#background-bash-commands): 대화를 차단하지 않고 하나의 셸 명령을 실행합니다. 에이전트를 생성하지는 않습니다.
* `/subtask`로 시작하는 [분기된 서브에이전트](/docs/en/sub-agents#fork-the-current-conversation): 새로 시작하는 대신 전체 대화 컨텍스트를 상속받는 서브에이전트입니다.
* [루틴(Routines)](/docs/en/routines): 사용자의 머신에서 병렬로 실행하는 것이 아니라 Anthropic 클라우드의 일정에 따라 세션을 실행합니다.

<Note>
  여러 세션이나 서브에이전트를 한 번에 실행하면 토큰 사용량이 배로 늘어납니다. 사용량 및 속도 제한에 대한 세부 정보는 [비용](/docs/en/costs)을 참고하세요.
</Note>

## 접근 방식 선택하기

적절한 접근 방식은 누가 작업을 조율하는지, 작업자 간 통신이 필요한지, 동일한 파일을 수정하는지에 따라 달라집니다:

* **누가 작업을 조율하나요?**
  * Claude가 단일 대화 내부에서 위임하고 결과를 수집함: [서브에이전트](/docs/en/sub-agents)
  * 사용자가 독립된 작업을 전달하고 나중에 확인함: [에이전트 뷰](/docs/en/agent-view)
  * Claude가 작업자 그룹을 계획하고, 할당하며, 감독함: [에이전트 팀](/docs/en/agent-teams) (실험적 기능)
  * 스크립트가 Claude의 턴바이턴 판단 대신 계획을 유지함: [동적 워크플로](/docs/en/workflows)
* **작업자 간에 대화가 필요한가요?** 서브에이전트는 자신을 생성한 대화로 결과를 보고하고, 에이전트 뷰 세션은 사용자에게만 보고합니다. 에이전트 팀의 팀원은 작업 목록을 공유하고 서로 직접 메시지를 주고받습니다.
* **작업이 동일한 파일을 다루나요?** [워크트리](/docs/en/worktrees)로 작업을 격리하세요. 서브에이전트와 직접 실행하는 세션은 각각 별도의 워크트리를 사용할 수 있습니다. 에이전트 팀은 팀원을 워크트리에 격리하지 않으므로 각 팀원이 다른 파일 집합을 소유하도록 [작업을 분할](/docs/en/agent-teams#avoid-file-conflicts)하세요.

## 실행 중인 작업 확인하기

실행 중인 작업을 확인하는 명령은 사용한 접근 방식에 따라 다릅니다:

* 백그라운드 세션의 경우 `claude agents`가 [에이전트 뷰](/docs/en/agent-view)를 엽니다.
* 현재 세션의 서브에이전트의 경우, 이름이 지정된 백그라운드 서브에이전트가 상태와 함께 @-mention 자동완성에 나타납니다.
* 현재 세션의 백그라운드에서 실행되는 모든 항목의 경우 `/tasks`가 각 항목을 나열하고 확인, 연결, 정지를 가능하게 합니다.
* 동적 워크플로의 경우 `/workflows`가 실행 중이거나 완료된 실행 목록, 진행 단계, 완료된 에이전트 수를 보여줍니다.

# Claude Code 확장하기

> CLAUDE.md, 스킬(Skills), 하위 에이전트(Subagents), 훅(Hooks), MCP 및 플러그인(Plugins)을 사용하는 시점을 이해하세요.

Claude Code는 코드를 추론하는 모델과 파일 작업, 검색, 실행 및 웹 접근을 위한 [내장 도구](/docs/en/how-claude-code-works#tools)를 결합합니다. 내장 도구는 대부분의 코딩 작업을 처리합니다. 이 가이드는 확장 레이어를 다룹니다: Claude가 알고 있는 지식을 맞춤 설정하고 외부 서비스에 연결하며 워크플로우를 자동화하기 위해 추가하는 기능들입니다.

<Note>
  핵심 에이전틱 루프 작동 방식은 [Claude Code 작동 방식](/docs/en/how-claude-code-works)을 참조하세요.
</Note>

**Claude Code가 처음이신가요?** 프로젝트 규칙을 다루는 [CLAUDE.md](/docs/en/memory)로 시작한 후 [특정 상황이 발생함에 따라](#build-your-setup-over-time) 다른 확장 기능을 추가하세요.

## 개요

확장 기능은 에이전틱 루프의 서로 다른 부분에 연결됩니다.

* **[CLAUDE.md](/docs/en/memory)**: Claude가 매 세션마다 확인하는 영구 컨텍스트 추가
* **[스킬 (Skills)](/docs/en/skills)**: 재사용 가능한 지식 및 호출 가능한 워크플로우 추가
* **[코드 인텔리전스 (Code intelligence)](/docs/en/tools-reference#lsp-tool-behavior)**: 심볼 수준 탐색 및 실시간 타입 오류를 위해 언어 서버에 Claude 연결
* **[MCP](/docs/en/mcp)**: 외부 서비스 및 도구에 Claude 연결
* **[하위 에이전트 (Subagents)](/docs/en/sub-agents)**: 격리된 컨텍스트에서 자체 루프를 실행하고 요약 반환
* **[에이전트 팀 (Agent teams)](/docs/en/agent-teams)**: 공유 작업 및 피어투피어 메시징으로 독립된 여러 세션 조율
* **[훅 (Hooks)](/docs/en/hooks-guide)**: 수명주기 이벤트 시 트리거되며 스크립트, HTTP 요청, 프롬프트 또는 하위 에이전트 실행 가능
* **[플러그인](/docs/en/plugins)** 및 **[마켓플레이스](/docs/en/plugin-marketplaces)**: 이러한 기능들을 번들링하여 배포

[스킬](/docs/en/skills)은 가장 유연한 확장 기능입니다. 스킬은 지식, 워크플로우 또는 지침이 담긴 마크다운 파일입니다. `/deploy`와 같은 명령으로 스킬을 직접 호출하거나, 관련이 있을 때 Claude가 자동으로 로드할 수 있습니다. 스킬은 현재 대화에서 실행되거나 하위 에이전트를 통해 격리된 컨텍스트에서 실행될 수 있습니다.

## 목적에 맞는 기능 선택

기능은 매 세션마다 Claude가 확인하는 상시 켜진 컨텍스트부터, 사용자나 Claude가 호출할 수 있는 온디맨드 기능, 특정 이벤트 시 실행되는 백그라운드 자동화까지 다양합니다. 아래 표는 사용 가능한 기능과 각 기능이 적합한 상황을 보여줍니다.

| 기능 | 수행 내용 | 적합한 사용 시점 | 예시 |
| :--- | :--- | :--- | :--- |
| **CLAUDE.md** | 모든 대화에 로드되는 영구 컨텍스트 | 프로젝트 규칙, "항상 X를 수행하라" 규칙 | "pnpm을 사용하고 npm은 사용하지 마라. 커밋 전 테스트를 실행하라." |
| **스킬 (Skill)** | Claude가 사용할 수 있는 지침, 지식 및 워크플로우 | 재사용 가능한 콘텐츠, 참조 문서, 반복 가능한 작업 | `/deploy`로 배포 체크리스트 실행; 엔드포인트 패턴이 담긴 API 문서 스킬 |
| **하위 에이전트 (Subagent)** | 요약된 결과만 반환하는 격리된 실행 컨텍스트 | 컨텍스트 격리, 병렬 작업, 특화된 작업자 | 많은 파일을 읽지만 핵심 결과만 반환하는 조사 작업 |
| **[에이전트 팀](/docs/en/agent-teams)** | 여러 독립된 Claude Code 세션 조율 | 병렬 조사, 새 기능 개발, 경쟁 가설을 통한 디버깅 | 보안, 성능, 테스트를 동시에 확인하는 리뷰어 생성 |
| **[코드 인텔리전스](/docs/en/tools-reference#lsp-tool-behavior)** | 언어 서버 탐색 및 진단 | 타입 언어, grep이 느리거나 부정확한 대규모 코드베이스 | 전체 파일을 읽는 대신 심볼의 정의로 이동 |
| **MCP** | 외부 서비스에 연결 | 외부 데이터 또는 작업 | 데이터베이스 쿼리, Slack 포스팅, 브라우저 제어 |
| **훅 (Hook)** | 이벤트 시 트리거되는 스크립트, HTTP 요청, 프롬프트, 하위 에이전트 | 일치하는 모든 이벤트 발생 시 항상 실행되어야 하는 자동화 | 파일 편집 후마다 ESLint 실행 |
| **[아티팩트 (Artifact)](/docs/en/artifacts)** | 세션 출력을 비공개 대화형 웹 페이지로 게시 | 터미널 텍스트 대신 시각적으로 보고 공유하고 싶은 출력 | Claude 조사에 따라 업데이트되는 장애 타임라인 |

**[플러그인](/docs/en/plugins)**은 번들링 레이어입니다. 플러그인은 스킬, 훅, 하위 에이전트, MCP 서버를 단일 설치 단위로 번들링합니다. 플러그인 스킬은 네임스페이스(`/my-plugin:review` 등)가 지정되어 여러 플러그인이 공존할 수 있습니다. 여러 리포지토리 전반에 걸쳐 동일한 설정을 재사용하거나 **[마켓플레이스](/docs/en/plugin-marketplaces)**를 통해 다른 사람들에게 배포하려는 경우 플러그인을 사용하세요.

### 시간에 따른 설정 구축

모든 것을 미리 구성할 필요는 없습니다. 각 기능에는 식별 가능한 계기가 있으며 대부분의 팀은 대략 다음 순서대로 기능을 추가합니다.

| 계기 | 추가할 기능 |
| :--- | :--- |
| Claude가 규칙이나 명령을 두 번 틀릴 때 | [CLAUDE.md](/docs/en/memory)에 추가 |
| 작업을 시작하기 위해 동일한 프롬프트를 계속 입력할 때 | 사용자가 호출 가능한 [스킬](/docs/en/skills)로 저장 |
| 동일한 뷰북이나 다단계 절차를 채팅에 세 번째 붙여넣을 때 | [스킬](/docs/en/skills)로 작성 |
| Claude가 볼 수 없는 브라우저 탭에서 데이터를 계속 복사해 올 때 | 해당 시스템을 [MCP 서버](/docs/en/mcp)로 연결 |
| Claude가 심볼이 정의되었거나 사용된 위치를 찾기 위해 많은 파일을 읽을 때 | 해당 언어용 [코드 인텔리전스 플러그인](/docs/en/discover-plugins#code-intelligence) 설치 |
| 사이드 작업으로 대화에 다시 참조하지 않을 출력이 가득 찰 때 | [하위 에이전트](/docs/en/sub-agents)로 라우팅 |
| 요청 없이 매번 실행되기를 원하는 항목이 있을 때 | [훅](/docs/en/hooks-guide) 작성 |
| 두 번째 리포지토리에 동일한 설정이 필요할 때 | [플러그인](/docs/en/plugins)으로 번들링 |

동일한 계기가 기존 항목을 업데이트할 시점도 알려줍니다. 반복되는 실수나 정기 리뷰 주석은 채팅에서의 일회성 수정이 아닌 CLAUDE.md 편집 대상입니다. 수동으로 계속 조정하는 워크플로우는 또 다른 개정이 필요한 스킬입니다.

### 유사한 기능 비교

일부 기능은 유사해 보일 수 있습니다. 선택에 대한 자세한 가이드는 블로그의 [Claude Code 조율하기: CLAUDE.md, 스킬, 훅, 하위 에이전트 사용 시점](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)을 참조하세요. 비교 내역은 다음과 같습니다.

<Tabs>
  <Tab title="스킬 vs 하위 에이전트">
    스킬과 하위 에이전트는 서로 다른 문제를 해결합니다.

    * **스킬**: 모든 컨텍스트로 로드할 수 있는 재사용 가능한 콘텐츠
    * **하위 에이전트**: 메인 대화와 별개로 실행되는 격리된 작업자

    | 구분 | 스킬 (Skill) | 하위 에이전트 (Subagent) |
    | :--- | :--- | :--- |
    | **개념** | 재사용 가능한 지침, 지식 또는 워크플로우 | 자체 컨텍스트를 갖는 격리된 작업자 |
    | **핵심 이점** | 컨텍스트 전반에 걸쳐 콘텐츠 공유 | 컨텍스트 격리. 작업은 별도로 진행되며 요약만 반환됨 |
    | **[컨텍스트 창](/docs/en/context-window) 영향** | 메인 창에 추가됨 | 자체 입력/출력 토큰을 갖는 별도 창 사용 |
    | **적합한 용도** | 참조 자료, 호출 가능한 워크플로우 | 많은 파일을 읽는 작업, 병렬 작업, 특화된 작업자 |

    **스킬은 참조 또는 동작이 될 수 있습니다.** 참조 스킬은 세션 동안 Claude가 사용하는 지식을 제공합니다(API 스타일 가이드 등). 동작 스킬은 배포 워크플로우를 실행하는 `/deploy`와 같이 구체적인 작업을 수행하도록 지시합니다.

    **하위 에이전트를 사용하는 시점**: 컨텍스트 격리가 필요하거나 컨텍스트 창이 가득 차갈 때 사용하세요. 하위 에이전트는 수십 개의 파일을 읽거나 광범위한 검색을 실행할 수 있지만 메인 대화에는 요약만 전달됩니다. 하위 에이전트 작업은 메인 컨텍스트를 소비하지 않으므로 중간 작업을 계속 노출할 필요가 없을 때 유용합니다. 커스텀 하위 에이전트는 자체 지침을 가질 수 있고 스킬을 사전 로드할 수 있습니다.

    **둘을 결합할 수 있습니다.** 하위 에이전트는 특정 스킬을 사전 로드할 수 있습니다(`skills:` 필드). 스킬은 `context: fork`를 사용하여 격리된 컨텍스트에서 실행할 수 있습니다. 세부 정보는 [스킬](/docs/en/skills)을 참조하세요.
  </Tab>

  <Tab title="CLAUDE.md vs 스킬">
    둘 다 지침을 저장하지만 로드 방식과 목적이 다릅니다.

    | 구분 | CLAUDE.md | 스킬 (Skill) |
    | :--- | :--- | :--- |
    | **로드 시점** | 매 세션마다 자동으로 | 필요 시 (On demand) |
    | **파일 포함 가능 여부** | 예 (`@path` 임포트) | 예 (`@path` 임포트) |
    | **워크플로우 트리거 가능 여부** | 아니요 | 예 (`/<이름>`) |
    | **적합한 용도** | "항상 X를 수행하라" 규칙 | 참조 자료, 호출 가능한 워크플로우 |

    **CLAUDE.md에 넣을 내용**: Claude가 항상 알아야 하는 규칙: 코딩 규칙, 빌드 명령, 프로젝트 구조, "절대 X를 하지 마라" 규칙.

    **스킬에 넣을 내용**: Claude가 가끔 필요로 하는 참조 자료(API 문서, 스타일 가이드)나 `/<이름>`으로 트리거하는 워크플로우(배포, 리뷰, 릴리스).

    **권장 규칙:** CLAUDE.md를 200줄 이하로 유지하세요. 파일이 커지면 참조 콘텐츠를 스킬로 이동하거나 [`.claude/rules/`](/docs/en/memory#organize-rules-with-claude/rules/) 파일로 분할하세요.
  </Tab>

  <Tab title="CLAUDE.md vs 규칙 vs 스킬">
    세 가지 모두 지침을 저장하지만 로드 방식이 다릅니다.

    | 구분 | CLAUDE.md | `.claude/rules/` | 스킬 (Skill) |
    | :--- | :--- | :--- | :--- |
    | **로드 시점** | 매 세션마다 | 매 세션마다, 또는 일치하는 파일이 열릴 때 | 호출되거나 관련이 있을 때 |
    | **범위** | 프로젝트 전체 | 파일 경로로 범위를 한정할 수 있음 | 특정 작업 전용 |
    | **적합한 용도** | 핵심 규칙 및 빌드 명령 | 언어별 또는 디렉토리별 지침 | 참조 자료, 반복 가능한 워크플로우 |

    **CLAUDE.md 사용 시점**: 모든 세션에 필요한 지침: 빌드 명령, 테스트 규칙, 프로젝트 아키텍처.

    **규칙(Rules) 사용 시점**: CLAUDE.md를 간결하게 유지하기 위함. [`paths` frontmatter](/docs/en/memory#path-specific-rules)가 있는 규칙은 Claude가 일치하는 파일로 작업할 때만 로드되어 컨텍스트를 절약합니다.

    **스킬(Skills) 사용 시점**: Claude가 API 문서나 `/<이름>`으로 트리거하는 배포 체크리스트처럼 가끔만 필요로 하는 콘텐츠.
  </Tab>

  <Tab title="하위 에이전트 vs 에이전트 팀">
    둘 다 작업을 병렬화하지만 아키텍처가 다릅니다.

    * **하위 에이전트**: 세션 내부에서 실행되며 결과를 메인 컨텍스트로 다시 보고
    * **에이전트 팀**: 서로 통신하는 독립된 Claude Code 세션들

    | 구분 | 하위 에이전트 (Subagent) | 에이전트 팀 (Agent team) |
    | :--- | :--- | :--- |
    | **컨텍스트** | 자체 컨텍스트 창; 결과는 호출자에게 반환됨 | 자체 컨텍스트 창; 완전히 독립적 |
    | **통신 방식** | 메인 에이전트에게만 결과 보고 | 팀원 간에 직접 메시지 전송 |
    | **조율 방식** | 메인 에이전트가 모든 작업 관리 | 자율 조율을 위한 공유 작업 목록 |
    | **적합한 용도** | 결과만 중요한 집중된 작업 | 토론과 협업이 필요한 복잡한 작업 |
    | **토론 비용** | 낮음: 결과가 메인 컨텍스트로 요약되어 반환됨 | 높음: 각 팀원이 별도의 Claude 인스턴스임 |

    **하위 에이전트 사용 시점**: 질문 조사, 주상 검증, 파일 리뷰 등 신속하고 집중된 작업자가 필요할 때. 하위 에이전트가 작업을 수행하고 요약을 반환하므로 메인 대화가 깨끗하게 유지됩니다.

    **에이전트 팀 사용 시점**: 팀원들이 결과를 공유하고, 서로 상의하며, 독립적으로 조율해야 할 때. 에이전트 팀은 경쟁 가설을 탐구하는 조사, 병렬 코드 리뷰, 각 팀원이 별도의 조각을 소유하는 새 기능 개발에 가장 적합합니다.

    <Note>
      에이전트 팀은 실험적 기능이며 기본적으로 비활성화되어 있습니다. 설정 및 제한 사항은 [에이전트 팀](/docs/en/agent-teams)을 참조하세요.
    </Note>
  </Tab>

  <Tab title="MCP vs 스킬">
    MCP는 Claude를 외부 서비스에 연결합니다. 스킬은 해당 서비스를 효율적으로 사용하는 방법을 포함하여 Claude가 알고 있는 지식을 확장합니다.

    | 구분 | MCP | 스킬 (Skill) |
    | :--- | :--- | :--- |
    | **개념** | 외부 서비스 연결 프로토콜 | 지식, 워크플로우 및 참조 자료 |
    | **제공 항목** | 도구 및 데이터 접근 | 지식, 워크플로우, 참조 자료 |
    | **예시** | Slack 연동, 데이터베이스 쿼리, 브라우저 제어 | 코드 리뷰 체크리스트, 배포 워크플로우, API 스타일 가이드 |

    서로 다른 문제를 해결하며 함께 잘 작동합니다.

    **MCP**는 서버에서 연결과 인증을 처리하여 외부 시스템용 전용 도구를 Claude에게 제공합니다.

    **스킬**은 해당 도구를 효율적으로 사용하는 지식과 `/<이름>`으로 트리거할 수 있는 워크플로우를 제공합니다. 스킬에는 팀의 데이터베이스 스키마와 쿼리 패턴, 또는 메시지 포맷팅 규칙이 담긴 `/post-to-slack` 워크플로우가 포함될 수 있습니다.

    예: MCP 서버가 Claude를 데이터베이스에 연결합니다. 스킬은 Claude에게 데이터 모델, 일반적인 쿼리 패턴, 작업별 사용 테이블을 가르칩니다.
  </Tab>

  <Tab title="훅 vs 스킬">
    훅은 수명주기 이벤트 시 실행되며, 스킬은 Claude가 적용할 수 있도록 컨텍스트에 로드됩니다.

    | 구분 | 훅 (Hook) | 스킬 (Skill) |
    | :--- | :--- | :--- |
    | **실행 방식** | 셸 명령, HTTP 요청, LLM 프롬프트, 하위 에이전트 | Claude가 읽고 따르는 지침 |
    | **트리거 계기** | `PostToolUse` 또는 `SessionStart`와 같은 [수명주기 이벤트](/docs/en/hooks#hook-events) | 사용자가 `/<이름>`을 입력하거나 Claude가 설명과 작업을 매칭할 때 |
    | **결정론성** | 이벤트 시 항상 실행됨; 트리거가 보장됨 | Claude가 지침을 해석함; 결과가 다를 수 있음 |
    | **컨텍스트 비용** | 훅이 출력을 반환하지 않는 한 0 | 매 세션마다 설명이 로드됨; 사용 시 전체 내용 로드 |
    | **적합한 용도** | 편집 후 린팅, 위험한 명령 차단, 로깅, 알림 | 추론이 필요한 워크플로우, 참조 자료, 다단계 작업 |

    **훅 사용 시점**: Claude의 판단 없이 매번 동일하게 실행되어야 하는 동작. 예: 저장 시 포맷팅, `rm -rf /` 거부, 세션 종료 시 Slack 메시지 전송.

    **스킬 사용 시점**: 단계를 적용하는 방법을 Claude가 결정해야 하거나 스크립트가 아닌 지식 형태인 경우. 예: `/release` 체크리스트, API 스타일 가이드, 디버깅 플레이북.

    **훅에 안전장치 배치**: CLAUDE.md나 스킬에 ".env를 절대 편집하지 마라"와 같은 지침은 요청이지 보장이 아닙니다. 편집을 차단하는 `PreToolUse` 훅이 강제 실행입니다. 규칙이 매번 유지되어야 하는 경우 프롬프트 지침이 아닌 훅으로 만드세요.

    **훅 출력의 컨텍스트 입력**: 린터를 실행하는 `PostToolUse` 훅은 결과를 Claude가 읽는 텍스트로 전달하며, `/fix-lint` 스킬은 Claude에게 이를 해결하는 방법을 알려줍니다.
  </Tab>
</Tabs>

### 기능 계층 구조 이해하기

기능은 사용자 전체, 프로젝트별, 플러그인 통해, 관리 정책 등 여러 수준에서 정의될 수 있습니다. 하위 디렉토리에 CLAUDE.md 파일을 중첩하거나 모노리포의 특정 패키지에 스킬을 배치할 수도 있습니다. 동일한 기능이 여러 수준에 존재할 때 적용되는 레이어링 방식입니다.

* **CLAUDE.md 파일**: 가산적(additive)입니다: 모든 수준이 동시에 Claude 컨텍스트에 기여합니다. 작업 디렉토리와 상위 디렉토리의 파일이 시작 시 로드되며, 작업하면서 하위 디렉토리의 파일이 로드됩니다. 지침이 충돌할 때 Claude는 판단을 적용하여 더 구체적인 지침을 우선시합니다. [CLAUDE.md 파일 로드 방식](/docs/en/memory#how-claude-md-files-load)을 참조하세요.
* **스킬 및 하위 에이전트**: 이름별 재정의: 여러 수준에 동일한 이름이 존재하는 경우 우선순위에 따라 하나의 정의가 사용됩니다 (스킬의 경우 관리 대상 > 사용자 > 프로젝트; 하위 에이전트의 경우 관리 대상 > CLI 플래그 > 프로젝트 > 사용자 > 플러그인). 플러그인 스킬은 충돌 방지를 위해 [네임스페이스가 지정](/docs/en/plugins#add-skills-to-your-plugin)됩니다. [스킬 탐색](/docs/en/skills#where-skills-live) 및 [하위 에이전트 범위](/docs/en/sub-agents#choose-the-subagent-scope)를 참조하세요.
* **MCP 서버**: 이름별 재정의: 로컬 > 프로젝트 > 사용자. [MCP 범위](/docs/en/mcp#scope-hierarchy-and-precedence)를 참조하세요.
* **훅**: 병합(merge): 출처에 관계없이 등록된 모든 훅이 일치하는 이벤트에 대해 실행됩니다. [훅](/docs/en/hooks)을 참조하세요.

### 기능 결합하기

각 확장은 서로 다른 문제를 해결합니다: CLAUDE.md는 상시 컨텍스트, 스킬은 온디맨드 지식과 워크플로우, MCP는 외부 연결, 하위 에이전트는 격리, 훅은 자동화를 처리합니다. 실제 환경에서는 워크플로우에 맞게 이들을 결합합니다.

예를 들어 프로젝트 규칙에는 CLAUDE.md, 배포 워크플로우에는 스킬, 데이터베이스 연결에는 MCP, 파일 편집 후 린팅 실행에는 훅을 사용할 수 있습니다. 각 기능이 가장 잘하는 영역을 담당하게 됩니다.

| 패턴 | 작동 방식 | 예시 |
| :--- | :--- | :--- |
| **스킬 + MCP** | MCP는 연결을 제공하고, 스킬은 Claude에게 잘 사용하는 방법을 가르침 | MCP가 데이터베이스에 연결하고, 스킬은 스키마와 쿼리 패턴을 문서화함 |
| **스킬 + 하위 에이전트** | 스킬이 병렬 작업을 위한 하위 에이전트를 생성함 | `/audit` 스킬이 격리된 컨텍스트에서 작동하는 보안, 성능, 스타일 하위 에이전트를 시작함 |
| **CLAUDE.md + 스킬** | CLAUDE.md는 상시 규칙을 유지하고, 스킬은 필요 시 로드되는 참조 자료를 유지함 | CLAUDE.md에 "API 규칙을 따르라"고 명시하고, 스킬에 전체 API 스타일 가이드를 담음 |
| **훅 + MCP** | 훅이 MCP를 통해 외부 작업을 트리거함 | Post-edit 훅이 Claude가 주요 파일을 수정할 때 Slack 알림을 전송함 |

## 컨텍스트 비용 이해하기

추가하는 모든 기능은 Claude 컨텍스트의 일부를 소비합니다. 너무 많으면 컨텍스트 창이 가득 찰 뿐만 아니라 소음이 추가되어 Claude의 효율성이 떨어질 수 있습니다(스킬이 올바르게 트리거되지 않거나 규칙을 놓칠 수 있음). 이러한 절충 관계를 이해하면 효율적인 설정을 구축할 수 있습니다. 진행 중인 세션에서 이들 기능이 결합하는 대화형 뷰는 [컨텍스트 창 탐색하기](/docs/en/context-window)를 참조하세요.

### 기능별 컨텍스트 비용

각 기능은 서로 다른 로딩 전략과 컨텍스트 비용을 가집니다.

| 기능 | 로드 시점 | 로드되는 내용 | 컨텍스트 비용 |
| :--- | :--- | :--- | :--- |
| **CLAUDE.md** | 세션 시작 | 전체 내용 | 매 요청 시 |
| **스킬 (Skills)** | 세션 시작 + 사용 시 | 시작 시 설명, 사용 시 전체 내용 | 낮음 (매 요청 시 설명)\* |
| **MCP 서버** | 세션 시작 | 도구 이름; 사용 시 전체 스키마 | 도구 사용 전까지 낮음 |
| **코드 인텔리전스** | 파일 편집 후 및 필요 시 | 편집 후 진단 정보; 조회 시 심볼 위치 | 낮음; 다른 파일 읽기를 줄여줌 |
| **하위 에이전트** | 생성 시 | 지정된 스킬이 포함된 신선한 컨텍스트 | 메인 세션과 격리됨 |
| **훅 (Hooks)** | 트리거 시 | 없음 (외부에서 실행됨) | 훅이 추가 컨텍스트를 반환하지 않는 한 0 |

\*기본적으로 Claude가 사용 시점을 결정할 수 있도록 세션 시작 시 스킬 설명이 로드됩니다. 스킬의 frontmatter에 `disable-model-invocation: true`를 설정하면 직접 수동으로 호출할 때까지 Claude에게 완전히 숨길 수 있습니다. 이렇게 하면 사용자가 직접 트리거하는 스킬의 컨텍스트 비용이 0이 됩니다. 작성하지 않은 스킬의 경우 설정에서 [`skillOverrides`](/docs/en/skills#override-skill-visibility-from-settings)를 설정하여 동일하게 적용할 수 있습니다.

### 기능별 로드 방식 이해하기

각 기능은 세션의 서로 다른 시점에 로드됩니다. 아래 탭은 각 기능이 로드되는 시점과 컨텍스트에 포함되는 내용을 설명합니다.

<Tabs>
  <Tab title="CLAUDE.md">
    **시점:** 세션 시작

    **로드 내용:** 모든 CLAUDE.md 파일(관리 대상, 사용자, 프로젝트 수준)의 전체 내용.

    **상속:** Claude는 작업 디렉토리부터 루트까지 CLAUDE.md 파일을 읽으며 해당 파일에 접근함에 따라 하위 디렉토리의 중첩 파일도 탐지합니다. 세부 정보는 [CLAUDE.md 파일 로드 방식](/docs/en/memory#how-claude-md-files-load)을 참조하세요.

    <Tip>CLAUDE.md를 200줄 이하로 유지하세요. 참조 자료는 필요 시 로드되는 스킬로 이동하세요.</Tip>
  </Tab>

  <Tab title="스킬 (Skills)">
    스킬은 Claude의 툴킷에 있는 추가 기능입니다. 참조 자료(API 스타일 가이드 등)이거나 `/<이름>`으로 트리거하는 호출 가능한 워크플로우(배포 등)일 수 있습니다. Claude Code에는 `/code-review`, `/batch`, `/debug`와 같이 바로 사용할 수 있는 [번들 스킬](/docs/en/commands)이 포함되어 있습니다. 직접 만들 수도 있습니다. 적절한 경우 Claude가 스킬을 사용하거나 사용자가 직접 호출할 수 있습니다.

    **시점:** 스킬 구성에 따라 다릅니다. 기본적으로 설명은 세션 시작 시 로드되고 전체 내용은 사용 시 로드됩니다. 사용자 전용 스킬(`disable-model-invocation: true`)의 경우 호출할 때까지 아무것도 로드되지 않습니다.

    **로드 내용:** 모델 호출 가능 스킬의 경우 매 요청 시 Claude가 이름과 설명을 확인합니다. `/<이름>`으로 스킬을 호출하거나 Claude가 자동으로 로드할 때 전체 내용이 대화로 로드됩니다.

    **Claude의 스킬 선택 방식:** Claude는 작업과 스킬 설명을 매칭하여 관련성 있는 스킬을 결정합니다. 설명이 모호하거나 중복되면 Claude가 잘못된 스킬을 로드하거나 도움이 되는 스킬을 놓칠 수 있습니다. 구체적인 스킬을 사용하도록 지시하려면 `/<이름>`으로 호출하세요. `disable-model-invocation: true`가 설정된 스킬은 사용자가 호출할 때까지 Claude에게 보이지 않습니다.

    **컨텍스트 비용:** 사용 전까지 낮음. 사용자 전용 스킬은 호출 전까지 비용이 0입니다.

    **하위 에이전트 내부:** 스킬은 하위 에이전트에서 다르게 작동합니다. 온디맨드 로드 대신 하위 에이전트의 `skills` 필드에 나열된 스킬은 시작 시 컨텍스트에 완전히 사전 로드됩니다. 하위 에이전트는 Skill 도구를 통해 나열되지 않은 프로젝트, 사용자, 플러그인 스킬을 탐색하고 호출할 수 있습니다.

    <Tip>사이드 이펙트가 있는 스킬에는 `disable-model-invocation: true`를 사용하세요. 컨텍스트를 절약하고 본인만 트리거하도록 보장합니다.</Tip>
  </Tab>

  <Tab title="MCP 서버">
    **시점:** 세션 시작.

    **로드 내용:** 연결된 서버의 도구 이름. 전체 JSON 스키마는 Claude가 특정 도구를 필요로 할 때까지 지연 유지됩니다.

    **컨텍스트 비용:** [도구 검색](/docs/en/mcp#scale-with-mcp-tool-search)이 기본적으로 켜져 있으므로 사용하지 않는 MCP 도구는 최소한의 컨텍스트만 소비합니다.

    <Tip>`/mcp`를 실행하여 서버별 연결 상태와 토큰 비용을 확인하세요. Claude Code는 연결이 끊어지면 [원격 서버에 자동으로 재연결](/docs/en/mcp#automatic-reconnection)하며, 활발히 사용하지 않는 서버는 연결 해제할 수 있습니다.</Tip>
  </Tab>

  <Tab title="코드 인텔리전스">
    **시점:** 파일 편집 후 및 Claude가 코드를 탐색할 때 필요 시.

    **로드 내용:** 매 파일 편집 후의 타입 오류 및 경고. Claude가 심볼을 조회할 때의 정의, 참조 및 타입 정보.

    **컨텍스트 비용:** 낮음. 심볼 조회가 광범위한 파일 읽기를 대체하므로 전체 순 컨텍스트 사용량이 줄어들 수 있습니다.

    <Tip>LSP 도구는 해당 언어용 [코드 인텔리전스 플러그인](/docs/en/discover-plugins#code-intelligence)을 설치할 때까지 비활성화 상태입니다.</Tip>
  </Tab>

  <Tab title="하위 에이전트">
    **시점:** 사용자나 Claude가 작업을 위해 하위 에이전트를 생성할 때 온디맨드로.

    **로드 내용:** 다음을 포함하는 신선하고 격리된 컨텍스트:

    * 전체 Claude Code 시스템 프롬프트가 아닌 에이전트 자체의 시스템 프롬프트
    * 에이전트의 `skills:` 필드에 나열된 스킬의 전체 내용
    * CLAUDE.md 및 git status (내장된 Explore 및 Plan 에이전트는 [둘 다 제외](/docs/en/sub-agents#what-loads-at-startup))
    * 리드 에이전트가 프롬프트로 전달하는 컨텍스트

    **컨텍스트 비용:** 메인 세션과 격리됨. 하위 에이전트는 대화 기록이나 호출된 스킬을 상속받지 않습니다.

    <Tip>전체 대화 컨텍스트가 필요하지 않은 작업에는 하위 에이전트를 사용하세요. 격리성 덕분에 메인 세션이 무거워지는 것을 방지합니다.</Tip>
  </Tab>

  <Tab title="훅 (Hooks)">
    **시점:** 트리거 시. 훅은 도구 실행, 세션 경계, 프롬프트 제출, 권한 요청, 축소 등 특정 수명주기 이벤트에 실행됩니다. 전체 목록은 [훅](/docs/en/hooks)을 참조하세요.

    **로드 내용:** 기본적으로 없음. 훅은 메인 대화 외부에서 실행됩니다.

    **컨텍스트 비용:** 훅이 대화에 메시지로 추가되는 출력을 반환하지 않는 한 0입니다.

    <Tip>훅은 Claude 컨텍스트에 영향을 줄 필요가 없는 사이드 이펙트(린팅, 로깅)에 이상적입니다.</Tip>
  </Tab>
</Tabs>
